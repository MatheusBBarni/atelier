# ADR-004: Resume safety model — drift interlock, capability re-consent, untrusted transcript

## Status

Accepted

## Date

2026-06-15

## Context

Resume **flips the event log from a passive audit record into an active, privileged input** that drives a live execution context. The Security Advocate's threat model identifies the relevant actors and failure modes for a local-trust tool:

- **Stale workspace state.** A resumed session's transcript may not match the current tree — recovery happens after a temporal gap (crash, quit, days later), exactly the window in which branches switch, rebases land, and pulls accumulate. A new prompt — or a half-applied patch the interrupted run left behind — can execute `ApplyPatch`/`WriteFile`/`RunCommand` against the **wrong tree**, silently corrupting a repo that can then be committed and pushed.
- **Confused deputy.** Resume re-adopts a session's roster, capabilities, and approval context the user may have forgotten — including `yolo` mode and broad write roots from days ago.
- **Untrusted bytes.** Stored transcripts are plaintext on disk; a crafted/tampered log can carry prompt-injection or terminal-escape sequences that render straight into the TUI.

The council converged that a **non-blocking warning is insufficient** (silent, irreversible, repo-scoped corruption), but a modal on *every* resume trains dismissal and taxes the clean common path — and gating on a **dirty tree is wrong** because a dirty tree is the *expected* state right after a crash.

## Decision

1. **Drift interlock at the first mutating action.** Detect drift as **cwd missing/moved or git HEAD changed** (branch switch / rebase / different commit) — **not** mere dirtiness. When drift is present, the **first state-mutating action** (`ApplyPatch`/`WriteFile`/`RunCommand`) after resume **folds the drift context into its approval prompt and requires positive acknowledgment**. The acknowledgment is recorded in the `session_resumed` event (ADR-002). **Read-only browse/preview is never gated.**
2. **Capability re-consent.** Resume **defaults to the restrictive `normal` approval mode**, so an approval always fires before any write/command. **Prior point-in-time approvals are never replayed as standing grants.** Re-elevation to `yolo` is a fresh, explicit user act. The resumed roster/capabilities/approval mode are displayed.
3. **Untrusted transcript.** Strip/escape control + ANSI sequences when rendering the read-only preview; frame replayed content to agents as historical record, not live directive.
4. **At-rest.** Enforce `0700` on the session directory and `0600` on session files. **Redaction-at-rest** (secrets/PII in stored prompts/outputs and any future search index) is a **named follow-up** with an explicit revisit trigger: the first non-solo / shared-host deployment.

## Alternatives Considered

### Alternative 1: Non-blocking warning only

- **Description**: Show a toast that the workspace may have changed; never block.
- **Pros**: Zero friction.
- **Cons**: A reflexive Enter (user racing back to their thread) becomes silent, irreversible repo corruption.
- **Why rejected**: A notification is not an interlock; the blast radius is unacceptable.

### Alternative 2: Block at session-open

- **Description**: Require acknowledgment before the session even opens.
- **Pros**: Simple placement.
- **Cons**: Fires on the happy path (and on every clean resume), trains users to mash through it, and blocks harmless read-only browsing.
- **Why rejected**: Gating the wrong moment destroys the gate's value.

## Consequences

### Positive

- Blocks **only where mutation meets drift**; the clean-resume common path has zero added friction.
- `yolo`-on-resume cannot silently write to a moved tree (an approval always fires under default `normal`).
- TUI is protected from malicious escape sequences in old logs.

### Negative

- Slightly more machinery at the approval surface and at `open()`.

### Risks

- At-rest plaintext secret exposure is **accepted for V1 as an explicitly-owned, triggered risk**, not waived silently.

## Implementation Notes

The drift check needs the session's stored `working_directory` (already in `SessionMetadata`) plus the live git HEAD; compute it during off-thread adoption (ADR-003) and carry it into the approval surface.
