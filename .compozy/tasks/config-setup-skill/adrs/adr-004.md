# ADR-004: Canonical skill in a top-level `skills/` directory with generated mirrors

## Status

Accepted

## Date

2026-06-15

## Context

The skill is named **`atelier-config-setup`**. Two discovery realities shape its layout:

- `npx skills add owner/repo` **recursively discovers every `SKILL.md`** in the repository.
- atelier discovers project roots `.agents/skills` + `.claude/skills` (and personal
  `~/.agents/skills` + `~/.claude/skills`); `.pi/skills` is not an atelier root.

The repo currently **hand-mirrors** skills across `.agents/skills`, `.claude/skills`, `.pi/skills`
as byte-identical copies with no enforcement — drift-prone. We need a single source of truth and a
clean publish surface for skills.sh.

## Decision

The canonical `SKILL.md` (+ `references/`) lives in a **new top-level `skills/atelier-config-setup/`**.
A sync target (`npm/scripts/sync-skills.mjs` or a `just` target) copies it into
`.agents/skills/atelier-config-setup/` and `.claude/skills/atelier-config-setup/` for atelier's own
runtime and Claude-Code dogfooding. **Mirrors are generated, never hand-edited**, and a CI check
asserts each mirror equals the canonical source. End users install by name:
`npx skills add MatheusBBarni/atelier atelier-config-setup`.

## Alternatives Considered

### Alternative 1: Canonical in `.agents/skills/atelier-config-setup/` + sync

- **Pros**: matches existing skill layout; no new top-level dir.
- **Cons**: couples the canonical source to a discovery dir; less clean as a publish surface.
- **Why rejected**: a dedicated `skills/` root reads more clearly as "the published skills".

### Alternative 2: Hand-maintained identical copies (status quo)

- **Pros**: zero tooling.
- **Cons**: copies drift with no enforcement.
- **Why rejected**: drift is exactly the failure mode this feature must avoid.

## Consequences

### Positive

- Single source of truth; clean publish surface; mirrors cannot drift (CI-enforced).

### Negative

- Adds a new top-level `skills/` directory, a sync script, and a mirror-equality CI check.

### Risks

- `npx skills add` still scans the mirror dirs, so a repo-wide scan lists the skill more than once —
  mitigate by documenting the **name-targeted** install. The `.pi/skills` mirror is optional
  (atelier does not discover it; include only if pi-dogfooding is wanted).

## Implementation Notes

- Sync script regenerates mirrors from `skills/atelier-config-setup/`; CI fails if a mirror differs.
- Skill alias resolves to `atelier-config-setup` (directory name + frontmatter `name`).
