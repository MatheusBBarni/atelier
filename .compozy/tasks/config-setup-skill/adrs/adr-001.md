# ADR-001: Portable config-setup skill, essentials-first whole-config wizard, consent-based skills.sh delivery

## Status

Accepted

## Date

2026-06-15

## Context

New atelier users must author `atelier.toml` by hand. The config has six sections
(`[agents.*] [presets.*] [runtimes.*] [council] [limits.*] [ui]` plus top-level
`approval_mode`/`workspace`/`preset`) and five enums (`RuntimeKind`, `ApprovalMode`,
`AgentEffort`, `Capability`, `ToolName`). `RawConfig` is `deny_unknown_fields`, so any
typo'd key or wrong enum value fails the whole load with an opaque error — onboarding is a
cliff. We want a default **skill** an LLM can invoke to produce a correct config, shipped so
users "install with npm", following the `skills.sh` convention.

Forces:

- **Distribution is nearly free.** Atelier already discovers skills from `.agents/skills`,
  `.claude/skills` (project) and `~/.agents/skills`, `~/.claude/skills` (personal) — the exact
  dirs `skills.sh` (`npx skills add owner/repo`) installs into.
- **Silent npm postinstall is a dying, distrusted pattern.** npm v12 (~July 2026) disables
  install scripts by default; pnpm v10 already blocks them; security guidance pushes
  `--ignore-scripts`. A postinstall also cannot safely prompt in CI/non-TTY. The user
  explicitly required that install "ask the user".
- **`--doctor` exits 0 today** (`cli.rs:157`), so self-validation must gate on
  `atelier --print-config` (which errors on invalid TOML), not on doctor's exit code.
- **A hand-written schema doc drifts** from the Rust source over time.
- The skill must serve **both** atelier's own runtime and external host agents (Claude Code,
  Cursor, Codex), which may not have `atelier` on PATH at first-config time.

## Decision

Ship a single **portable `SKILL.md`** (`config-setup`) with minimal `name` + `description`
frontmatter (atelier-compatible; richer frontmatter tolerated by host agents) that:

1. **Covers the whole config, essentials-first.** A short guided wizard collects runtime →
   model (+ fallbacks) → `approval_mode` → one starter agent, then progressively discloses
   `presets`, `council`, `limits`, `ui`, `workspace`. It documents every section, enum, the
   merge order, and the file locations.
2. **Self-validates with graceful degradation.** If `atelier` is on PATH, run
   `atelier --print-config` (and `--doctor`) and fix until clean; otherwise write
   schema-correct TOML and instruct the user to run `atelier --doctor`. No hard dependency on
   atelier being runnable by the host agent.
3. **Anchors to generated truth (anti-drift).** The skill instructs the agent to read
   `atelier --init-config` / `--print-config` output as ground truth before editing, and is
   pinned to the config `schema_version`.
4. **Is delivered over the `skills.sh` consent rail.** Published so `npx skills add
   MatheusBBarni/atelier` installs the `SKILL.md` into the user's skills dir, and bundled in
   atelier's own repo skill dirs so atelier's runtime sees it. Any npm lifecycle script only
   **prints a one-line hint**; it never writes to skills dirs without explicit, TTY-gated
   consent (`--yes` for CI).

V2 (deferred, not part of this decision): a multi-skill pack (`add-runtime`, `add-agent`,
`troubleshoot-doctor`) and native `atelier --emit-config-schema` + `atelier setup`.

## Alternatives Considered

### Alternative 1: Silent npm postinstall that auto-copies the skill

- **Description**: A `postinstall` script copies the SKILL.md into `~/.claude/skills` /
  `~/.agents/skills` on `npm install`.
- **Pros**: Zero extra step; "just works" after install.
- **Cons**: npm v12/pnpm disable install scripts by default; flagged as supply-chain risk;
  cannot prompt for consent in CI/non-TTY; violates the user's "ask the user" requirement.
- **Why rejected**: The mechanism is being removed from the ecosystem and is unsafe/unconsented;
  a postinstall can at most print a hint.

### Alternative 2: Native-only interactive setup (no skill)

- **Description**: Build `atelier setup` + `atelier --emit-config-schema` in Rust and skip the
  portable skill.
- **Pros**: Kills schema drift at the root (schema generated from source); first-class UX.
- **Cons**: Real core Rust work; does nothing for external host agents that want to configure
  atelier before/without running it; misses the "skill installable via npm" requirement.
- **Why rejected**: Higher cost, narrower reach; folded into V2 as the anti-drift end-state.

### Alternative 3: Essentials-only skill (runtime + model + approval only)

- **Description**: V1 covers just the 80% path; advanced sections become a reference appendix.
- **Pros**: Ships fastest; smallest drift surface.
- **Cons**: Power users still hand-edit presets/council/limits; the "configure the whole file"
  promise is unmet.
- **Why rejected**: Whole-config coverage is the entry-point value; we keep it but sequence it
  essentials-first (adopts this alternative's ordering without dropping coverage).

## Consequences

### Positive

- Removes the #1 first-run blocker; portable expertise usable by any agent.
- Reuses existing skill-discovery dirs and `--print-config` — minimal new surface.
- Consent-based delivery is future-proof against npm v12/pnpm and security policy.
- Establishes a reusable `skills.sh` distribution rail for all future atelier skills.

### Negative

- A Markdown skill is trivially copyable (low raw defensibility; moat = canonical + synced).
- Two consumers (atelier runtime + external agents) means the prose must stay engine-agnostic.

### Risks

- **Schema drift** — mitigated by anchoring to `--init-config`/`--print-config` output and
  pinning to `schema_version`; add a CI check that the skill's enum lists match the source.
- **Install friction** — `npx skills add` is an explicit step; mitigated by a printed hint and
  docs. Consider a first-class `atelier skills install` subcommand in V2.
- **False "valid" signal** — `--doctor` exits 0 today; gate validation on `--print-config` and
  adopt `--doctor --strict` (sibling `config-validation-ux` packet) once available.

## Implementation Notes

- SKILL.md lives in the repo so it ships and atelier's runtime discovers it (e.g. a canonical
  source dir mirrored into `.agents/skills/config-setup/` and `.claude/skills/config-setup/`).
- Keep frontmatter to `name` + `description` for atelier; the body carries the schema reference
  and wizard protocol, with a runtime disclaimer (skills are guidance; don't bypass approvals).
- Version-sync the skill with the config `schema_version`, mirroring the Cargo↔npm version gate.
