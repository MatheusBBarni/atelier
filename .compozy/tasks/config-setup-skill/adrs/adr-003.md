# ADR-003: V1 builds config greenfield; importing existing tool conventions is out of scope

## Status

Accepted

## Date

2026-06-15

## Context

The same "new user, empty `atelier.toml`" problem is also targeted by a separate roadmap item,
the **"Config importer"** (`atelier import-config --from claude-code|cursor|codex`), which
derives a starter config from a repo's existing `CLAUDE.md` / `.claude/skills` / `.mcp.json`.
Without an explicit boundary, the config-setup skill could drift into importing existing
conventions — duplicating that feature and bloating the skill body past the < 500-line guidance.

## Decision

V1 of `config-setup` builds a **fresh `atelier.toml` interactively** (with named presets) and
does **not** read or import a repo's existing agent-tool configuration. Importing existing
conventions remains owned by the config-importer roadmap item. The two compose later: the
importer seeds a config, the skill refines it.

## Alternatives Considered

### Alternative 1: Detect & mention existing conventions

- **Description**: Notice existing `.claude/skills` / `CLAUDE.md` and surface them, but still
  build interactively.
- **Pros**: a soft bridge to the importer; mild convenience.
- **Cons**: adds discovery logic and an overlap surface to maintain.
- **Why rejected**: scope creep for marginal V1 value.

### Alternative 2: Import in this skill

- **Description**: Fold reading existing conventions into V1 to pre-seed config.
- **Pros**: one-stop setup for users with rich existing config.
- **Cons**: directly duplicates the config-importer roadmap item.
- **Why rejected**: two features owning the same capability invites divergence.

## Consequences

### Positive

- Tight scope, zero overlap, smaller skill body, faster ship.

### Negative

- A user with rich existing conventions re-answers some questions the importer could auto-fill
  (acceptable; the importer is the future bridge).

### Risks

- User confusion about which feature does what — mitigate with a docs cross-reference between
  config-setup and config-importer.

## Implementation Notes

- The wizard's named presets cover the common greenfield setups; no repo inspection in V1.
