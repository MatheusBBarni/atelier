# ADR-004: Docs site as all-Markdown Astro content collections with derived machine-readable twins

## Status

Accepted

## Date

2026-06-12

## Context

The `/docs` section needs five pages serving a first-time evaluator, a returning
configurer, and LLMs — reusing the bespoke `global.css` design system and deploying under
base path `/atelier`. Astro 6.4.4 supports **content collections** and **static endpoint
routes** in core (no new dependency); MDX is **not** installed (would add one). The
machine-readability goal (PRD F5) requires per-page `.md` twins + `llms-full.txt` +
`llms.txt` + a sitemap. There is no shared layout today — head, fonts, and nav are inline
in `web/src/pages/index.astro`.

## Decision

Author all docs pages as **Markdown in one Astro content collection**
(`web/src/content/docs/`):

- **Prose pages** (Quickstart, Concepts, Governance & Safety) are hand-written and
  committed.
- **Reference pages** (Configuration, CLI & Commands) are emitted as `.md` by the
  generator (ADR-003) into the same collection — git-ignored, regenerated at build.

A single `DocsLayout` renders every entry to HTML, reusing `global.css` tokens with a
doc-sized heading scale and themed Markdown tables. Machine-readable surfaces are static
**endpoint routes**:

- `src/pages/docs/[slug].md.ts` — emits each page's raw Markdown twin;
- `src/pages/llms-full.txt.ts` — concatenates all non-Optional entries;
- `src/pages/llms.txt.ts` — emits the curated index (H1 + summary + link sections, with a
  `## Optional` bucket);
- a sitemap emitted likewise.

Extract a shared **`Base.astro`** (head, fonts, nav, footer) used by both the landing page
and `DocsLayout`. All cross-page links use the `BASE_URL`-relative helper from
`index.astro:3-6` — never a hardcoded `/docs/...`.

## Alternatives Considered

### Alternative 1: Hybrid — prose Markdown + reference as `.astro` importing JSON

- **Description**: Reference pages are `.astro` that import generator JSON and render the
  bespoke `.command-table`.
- **Pros**: Pixel-identical reference styling.
- **Cons**: Reference `.md` twins need a separate generation path; non-uniform rendering;
  more moving parts.
- **Why rejected**: Uniform Markdown gives twins + `llms-full.txt` for free; visual
  fidelity is a minor, themeable trade.

### Alternative 2: Add `@astrojs/mdx`

- **Description**: Author pages as MDX for richer components.
- **Pros**: Components inside content.
- **Cons**: A new dependency for capability plain `.md` + endpoints already cover.
- **Why rejected**: YAGNI — avoid the dependency.

### Alternative 3: Keep everything inline `.astro` with hand-written twins

- **Description**: No content collection; pages are `.astro`, twins authored by hand.
- **Pros**: No new structure.
- **Cons**: Duplication and twin drift.
- **Why rejected**: Reintroduces the drift this project exists to remove.

## Consequences

### Positive

- One rendering path; `.md` twins + `llms-full.txt` derive uniformly and for free.
- Zero new dependencies.
- Prose and generated reference coexist in one collection; `Base.astro` removes head/nav
  duplication across the landing page and docs.

### Negative

- Reference tables render as themed Markdown tables, not the pixel-identical
  `.command-table`.
- A small theming pass is needed for Markdown elements (tables, code, headings).
- The content directory mixes committed (prose) and git-ignored (generated) entries.

### Risks

- **Base-path 404s** if a link bypasses the helper → enforced by the ADR-005 link-check.
- **Markdown-table styling drifting from the brand** → add doc-specific CSS tokens.

## Implementation Notes

- `web/src/content.config.ts` defines the `docs` collection with a `glob()` loader over
  `src/content/docs/**`; frontmatter carries `title`, `nav_order`, and `llms_optional`
  (to bucket the `## Optional` section of `llms.txt`).
- Endpoints import `getCollection('docs')` and use `render()` / the entry's raw body.
