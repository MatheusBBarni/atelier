# ADR-001: V1 docs — derive reference from the Rust source and ship alongside the README

## Status

Accepted

## Date

2026-06-12

## Context

Atelier is adding documentation to its existing Astro marketing site (`web/`). The
owner scoped a small multi-page `/docs` section (~4-6 pages) serving both first-time
evaluators and hands-on configurers, positioned as a "Strategic Bet" activation /
acquisition surface, with the intent that docs become the canonical source of truth
(the README slimming to a pointer).

Two facts dominate the decision:

- The real source of truth for commands, flags, and config lives in Rust
  (`src/slash_commands.rs`, `src/cli.rs`, `src/config/mod.rs`, `src/runtime/mod.rs`).
  The site's existing hand-maintained command tables (`web/src/pages/index.astro`)
  are **already stale** against it — direct proof that hand-authored reference content
  drifts on a small team.
- The site is Astro 6.3.1 with **no shared layout/component layer** and deploys to
  GitHub Pages under base path `/atelier`, where cross-page links can pass locally
  (`/`) but 404 in production — and no base-correct cross-page link example exists yet.

A five-advisor council (pragmatic-engineer, architect-advisor, product-mind,
devils-advocate, the-thinker) debated tooling, scope, the README-canonical migration,
drift, and the 10x framing. It reached strong consensus on deriving reference from
source and shipping alongside the README; it left tooling (Starlight vs hand-rolled)
to the owner.

## Decision

Ship a V1 documentation section whose **reference content is generated from the Rust
source**, hand-authoring only irreducibly human prose, and **ship it alongside the
README** rather than replacing it:

- **V1 page set (~5 pages):**
  1. **Quickstart** — install → `atelier --doctor` → first orchestrated run in
     < 5 minutes, with 1-2 real copy-paste recipes seeded inline.
  2. **Configuration reference** — `multiagent.toml` (agents, presets, runtimes,
     council, limits, ui), **generated** from `src/config/mod.rs`.
  3. **Commands & CLI reference** — slash commands + CLI flags, **generated** from
     `src/slash_commands.rs` and `src/cli.rs`.
  4. **Governance & Safety** — hand-written, source-anchored: approval modes
     (yolo/normal), capabilities, read/write roots, limits, and the durable
     event-sourced record. The category's unclaimed differentiator.
  5. **Troubleshooting** — thin, seeded only from the 2-3 known first-run failures
     (missing API key, runtime CLI not installed, config won't parse).
- **Discoverability assets in V1:** `llms.txt` (+ `llms-full.txt`) and a sitemap, so
  LLMs cite Atelier accurately instead of hallucinating its flags.
- **Source of truth = the generator.** "Canonical" means the derived corpus, of which
  both the README tables and the site pages are projections.
- **README stays canonical and never-404 in V1** (keeps the quickstart + generated
  tables); the README→pointer flip is **deferred to V2**, earned by a verified
  production deploy plus demonstrated audience demand.
- **Ship behind a CI link-check gate** (e.g. lychee/linkinator over `dist/` in the
  Pages workflow) so base-path 404s fail the deploy instead of reaching users.
- **In-product `/help` that RAGs the docs is deferred to V2** as a fast-follow the
  corpus makes possible.

Tooling (Astro Starlight vs hand-rolled multi-page over the existing `global.css`) is
recorded as an open owner decision (see Alternatives). The owner's stated preference is
hand-rolled; the rebuttal round confirmed a generator + a minimal shared layout + an
`llms.txt` emitter delivers the needed machine-readability **without** adopting a
framework.

## Alternatives Considered

### Alternative 1: Hand-author the reference pages

- **Description**: Write command/flag/config tables by hand in Astro markup.
- **Pros**: No generator to build; full formatting control.
- **Cons**: Guaranteed drift — the existing hand tables are already stale.
- **Why rejected**: Drift is the only *proven* failure on the table; codegen ends the
  entire bug class.

### Alternative 2: Adopt Astro Starlight now

- **Description**: Mount Starlight for the `/docs` subtree (free search, sitemap,
  versioning, dark mode, `llms.txt` plugins).
- **Pros**: Table-stakes docs machinery maintained upstream; fastest path to "real docs."
- **Cons**: Owner explicitly declined a full framework; introduces a second visual
  language and a dependency to reconcile with the bespoke landing page.
- **Why deferred**: A generator + minimal shared layout + `llms.txt` emitter covers the
  load-bearing needs without a framework. Revisit when search/versioning become necessary.

### Alternative 3: Minimalist — README + quickstart + llms.txt only (no site pages)

- **Description**: Tighten the README, add a quickstart and generated tables, ship
  `llms.txt`; build no separate docs pages yet.
- **Pros**: Smallest blast radius; validates audience before investing.
- **Cons**: Abandons the activation-surface goal and the differentiated Governance page;
  leaves a long, unscannable README.
- **Why rejected**: Under-delivers on the owner's "Strategic Bet" — but its discipline is
  absorbed (derive-from-source, `llms.txt`, README-stays-canonical-in-V1).

### Alternative 4: Flip the README to a pointer in V1

- **Description**: Slim the README to intro + "full docs →" immediately.
- **Pros**: Single human-facing canonical surface; no duplication.
- **Cons**: Points the zero-cost, never-404 GitHub storefront at a first-ever Pages
  deploy carrying base-path 404 risk; strands GitHub-first visitors if a link breaks.
- **Why deferred to V2**: A niche OSS tool's first impression shouldn't ride on an
  unproven deploy; flip on evidence, not on one green build.

## Consequences

### Positive

- Reference content cannot drift from the code — kills the proven failure mode.
- Sub-5-minute time-to-first-success is the V1 north star; conversion-first ordering.
- Ships the category's unclaimed differentiator (Governance & Safety) in V1.
- Safe rollout: the README keeps working; the site proves itself before becoming canonical.
- `llms.txt` makes Atelier citable by LLMs — the real top-of-funnel for a niche tool.
- Lays the corpus foundation that makes a V2 in-product `/help` RAG cheap.

### Negative

- Building the generator/codegen is upfront engineering before any page ships.
- Two human-maintained prose pages (Quickstart, Governance) still require care.
- Without MDX, reference pages render as plain `<pre>` (no syntax highlighting) until a
  later MDX/Starlight decision.
- Temporary duplication: README tables and site reference both project from the
  generator until the V2 flip.

### Risks

- **Base-path 404s** (links pass at `/`, fail at `/atelier`) — mitigated by the CI
  link-check gate before deploy.
- **Generator complexity / scope creep** — mitigate by emitting structured data from
  existing surfaces (`--print-config`, `--doctor --json`, the `slash_commands.rs`
  catalog) rather than bespoke parsing; start with the highest-churn tables.
- **Two-projection divergence** before the V2 flip — mitigate by generating both the
  README tables and the site pages from the one emitter.

## Implementation Notes

- Prefer emitting machine-readable data from existing Rust surfaces: `atelier
  --print-config` (redacted), `atelier --doctor --json`, and the metadata-only
  `slash_commands.rs` catalog; consume at build time.
- Extract a shared `web/src/layouts/Base.astro` (head, fonts `<link>`, nav, footer)
  before adding pages, so the head/nav/font block isn't copy-pasted per page.
- Reuse existing primitives: `.section`, `.eyebrow`, `.command-table` `<dl>`,
  `.feature-card`, `.install__panel`, and the `assetPath()`/`basePath` helper for every
  cross-page link.
- Add a smaller doc-heading scale; the marketing `h1/h2` (up to 12rem / 5.8rem) are too
  large for doc body.
