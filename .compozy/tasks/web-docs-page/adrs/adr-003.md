# ADR-003: Reference generator — a Rust `--emit-docs` subcommand executed at build time

## Status

Accepted

## Date

2026-06-12

## Context

The docs require reference content (config schema, CLI flags, slash commands) that must
not drift from the Rust source of truth — the site's current hand-maintained tables are
already stale. The relevant surfaces are available in-process:

- merged config via `to_redacted_toml` / the private `PrintableConfig`
  (`src/config/mod.rs:1866`, `:1792`) — TOML, redacted, but `[presets.*]` is **absent**
  from `EffectiveConfig` (only the active preset *name* is emitted);
- the full CLI surface via `Cli::command()` (clap `CommandFactory`, already used at
  `src/cli.rs:179`);
- the slash catalog via `slash_commands::catalog()` (`src/slash_commands.rs:119`).

`run_doctor` is serde-serializable (`src/doctor/mod.rs:55`, `:241`) **but
non-deterministic** (timestamp + live CLI probes). There is no `xtask`/`build.rs`/codegen
precedent; `--codemap` (a value-enum flag that walks the tree and writes `codemap.md`
files, `src/codemap/mod.rs:111`,`:351`,`:391`) is the established "binary subcommand that
writes generated files" pattern. The GitHub Pages build uses the Node-only
`withastro/action` and cannot run a Rust binary.

## Decision

Implement the generator as a new flag on the `atelier` binary — `atelier --emit-docs
<out-dir>` — dispatched in `run_cli_with` after the `--print-config` handler, mirroring
`--codemap`. It reads, in-process: the redacted merged config (reusing the
`to_redacted_toml`/`PrintableConfig` builder, factored to also emit a structured/Markdown
form), `Cli::command()` for the flag list, and `slash_commands::catalog()` for the
command catalog. It emits **Markdown** reference fragments (per ADR-004) into the Astro
content collection.

- `[presets.*]` is sourced from the `--init-config` starter template (the only place
  presets are materialized), not from the merged config.
- **Troubleshooting is hand-written** from the doctor checks' static remediation strings;
  doctor's *live* output is not generated into docs because it is non-deterministic.
- No new Rust types are required: the generator reads `catalog()` directly, so the slash
  types need **no `Serialize` derive** (resolving a PRD open question).

The generator runs **at build time, not as a committed artifact**: a custom Pages
workflow (ADR-005) builds the binary and runs `--emit-docs` before `astro build`; local
dev runs it via a `web/package.json` script. A Rust **coverage test** asserts the
generator emits every slash command, CLI flag, and config section.

## Alternatives Considered

### Alternative 1: Node/TS build script shelling out to the binary

- **Description**: A `web/` script runs `atelier --print-config` / `--doctor --json` and
  parses the output into page data.
- **Pros**: No new Rust code.
- **Cons**: Must parse TOML; cannot see the slash catalog (unexposed by any command);
  consumes non-deterministic doctor output; couples docs to a fragile parsing layer.
- **Why rejected**: In-process access is strictly simpler and more robust.

### Alternative 2: Commit generated fragments + a git-clean drift gate

- **Description**: Run the generator locally, commit the fragments, and a CI check asserts
  re-running leaves `git` clean.
- **Pros**: The Pages pipeline stays Node-only; diffs are reviewable.
- **Cons**: Generated artifacts live in the repo; easy to forget regeneration.
- **Why rejected**: The owner chose build-time generation (always fresh, no committed
  artifacts).

### Alternative 3: An `xtask` / `build.rs` codegen crate

- **Description**: A separate build crate or build script performs generation.
- **Pros**: Conventional codegen placement.
- **Cons**: No precedent; the project is a single-package manifest.
- **Why rejected**: A gated subcommand is lighter and mirrors the existing `--codemap`.

## Consequences

### Positive

- Reference cannot drift — it is regenerated on every build from the one source of truth.
- No output parsing; the binary owns its own docs.
- The coverage test fails CI on any undocumented flag/command/config surface.

### Negative

- The Pages pipeline must gain a Rust toolchain (ADR-005), making web deploys heavier.
- The `PrintableConfig` builder must be factored to also emit a structured/Markdown form.
- `[presets.*]` and Troubleshooting remain hand-written exceptions.

### Risks

- **Non-determinism would break reproducible builds** → exclude doctor's live output;
  emit with stable ordering (sorted keys/commands).
- **Config-builder refactor risk** → guarded by the coverage test and existing config tests.

## Implementation Notes

- Add `emit_docs: Option<PathBuf>` near `src/cli.rs:44`; a `bail!` exclusion guard at
  `src/cli.rs:58-84` (and into the `--update` OR-chain); the handler after
  `src/cli.rs:131` (it needs the merged `config`).
- Follow `codemap::write_maps` / `render_folder_map` for file-writing and the
  Markdown-by-`format!` idiom (`src/codemap/mod.rs:351`,`:391`).
