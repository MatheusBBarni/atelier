## Shared Decisions
- Docs scaffold contract (task_03): one `docs` content collection (`web/src/content.config.ts`, `glob` over `src/content/docs`, frontmatter `title`/`nav_order`/`llms_optional`; `**/*.md` pattern deliberately includes `_`-prefixed so `_generated/` reference is picked up). Pages render through `web/src/layouts/DocsLayout.astro`, which itself fetches `getCollection('docs')` for the section nav and takes props `entry` + `headings` (from `render(entry)`). Routes: `web/src/pages/docs/index.astro` (lists by `nav_order`) + `[...slug].astro` (one static path per `entry.id`). All links go through `assetPath`/`BASE_URL` — never hardcode `/docs/...`. Prose (task_04–06) and generated `_generated/*.md` (task_11) just drop `.md` files into the collection. Endpoints (task_07) read the same collection via `getCollection`/`render`. Empty collection builds fine (index shows an empty state). Themed doc CSS lives at the end of `web/src/styles/global.css` (`.doc-prose`, `.docs__*`, `.docs-index__*`).
- Astro 6 content-layer gotcha: the glob data store caches in `node_modules/.astro/data-store.json` (and `web/.astro/`). Removing a `.md` does not drop its stale route — clear `node_modules/.astro` + `.astro` before rebuilds that test removed/zero entries.
- Shared layout contract (task_02): `web/src/layouts/Base.astro` owns `<head>` (charset/viewport/description/title/theme-color `#08131f`/favicon/apple-touch-icon/Google Fonts/`global.css`) + body shell. Props: `title`, `description`, optional `canonical`, `ogImage`, `renderHeader` (default `true`). Named slots: default content, `head`, `footer` (footer only renders when provided). Nav markup is in `web/src/components/Nav.astro`; `assetPath`/`basePath` are in `web/src/lib/basePath.ts` — import these, never re-inline the base-path helper. Landing page (`index.astro`) keeps its nav inside the hero via `renderHeader={false}`; docs pages get the top nav for free.

- Machine-readable surfaces (task_07): pure builders in `web/src/lib/machineSurfaces.mjs` (plain JS, importable by `.ts` endpoints AND `node --test`); endpoints are thin `.ts` files (`llms.txt.ts`, `llms-full.txt.ts`, `docs/[...slug].md.ts`, `sitemap.xml.ts`) that `getCollection('docs').map(fromCollectionEntry)` then call a builder. All `export const prerender = true`. Absolute URLs = `context.site.origin` + normalized `import.meta.env.BASE_URL` + `docs/<id>/`. Web test convention established: `npm test` = `node --test tests/**/*.test.mjs` (no vitest/TS-loader); post-build integration check is `npm run check:surfaces` (`scripts/check-dist-surfaces.mjs`, base-aware via `GITHUB_PAGES`) — task_08's web-checks gate can call it.

## Shared Learnings
- Prose cross-link convention (task_04, for task_05/06): Markdown body links CANNOT use `assetPath`/`BASE_URL`. Use relative `../<slug>/` (e.g. `../concepts/`, `../governance/`) — base-agnostic, resolves under both `/` (local) and `/atelier` (Pages) thanks to the directory build format + trailing-slash nav. Targets that don't exist yet build fine locally but will 404 in a lychee link-check (task_08) until the sibling page lands.
- Approval/control-plane facts (verified in task_04, reusable for Governance task_06): default `approval_mode = "yolo"` (auto-approve, no prompt); set `"normal"` to be asked. Only write/command actions pause for approval, never reads. Approval chat item title "Action approval required" + `$ <cmd>` body (`src/app/chat/projection.rs:577`); approve with `y`/`yes`/`approve` (`src/tui/mod.rs:1178`). `fake` runtime's prompt control phrases are TEST scaffolding (`src/runtime/fake.rs`) — do not document them as product features.
