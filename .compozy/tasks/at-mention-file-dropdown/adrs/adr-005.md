# ADR-005: Component Placement and Dropdown Integration

## Status

Accepted

## Date

2026-06-12

## Context

All existing dropdowns (agent, skill, command) live in `src/tui/mod.rs` and share
the token detector (`active_prompt_token`), insertion/cursor helpers, and render
scaffolding. ADR-001 wanted the filesystem-touching index in a non-TUI module
with a single insertion join point and a structured candidate type.

The `@` dropdown is token-based (like the skill dropdown) but also needs an
empty/no-match state (like the command dropdown), Esc-dismissal, and Tab/Enter
acceptance, and it must **consume the `@`** on insert so the result is a bare
path.

## Decision

- **Dropdown in `src/tui/mod.rs`:** place the dropdown state, activation
  (`file_mention_dropdown`), key handling, render
  (`render_file_mention_dropdown`), and insertion alongside the existing
  dropdowns, reusing `active_prompt_token`, the insertion/cursor helpers, and the
  upward-overlay render pattern.
- **Index in a new `src/file_index.rs`:** a single new crate-root module (not a
  new directory/package — YAGNI) owns `FileEntry`, the `ignore`-crate walk, the
  secret/force-exclude filtering, and the `nucleo-matcher` query. The TUI never
  walks the filesystem directly.
- **State shape:** model `FileMentionDropdown` on `SkillDropdown` (carries a
  `PromptToken`) plus a `CommandDropdown`-style `empty` flag; add a
  `FileMentionDropdownCommand { Previous, Next, Accept, Dismiss }` and a
  `file_mention_dropdown_dismissed: Option<String>` mirroring the command
  dropdown's Esc-dismissal.
- **Insertion:** mirror `apply_skill_suggestion`, but extend the replaced range
  back over the `@` prefix so the inserted text is a **bare path** (folders get a
  trailing `/`); add a trailing space and place the cursor after it (enabling
  multi-reference by re-typing `@`).

## Alternatives Considered

### Alternative 1: Everything in `src/tui/mod.rs`

- **Description**: Put the walk and index in the TUI module too.
- **Pros**: Fewer files.
- **Cons**: Keeps the filesystem walk in the TUI module, against ADR-001's
  isolation goal; harder to unit-test the walk independently.
- **Why rejected**: The walk belongs off the TUI surface.

### Alternative 2: A new module directory/package (`src/files/`)

- **Description**: Create a multi-file module directory.
- **Pros**: Room to grow.
- **Cons**: YAGNI — a single file suffices for V1.
- **Why rejected**: Premature structure.

### Alternative 3: Keep the `@` in the inserted text

- **Description**: Replace only the token value (like agent/skill), leaving `@`.
- **Pros**: Reuses the exact replacement range.
- **Cons**: The PRD chose a bare path.
- **Why rejected**: Contradicts the approved UX.

## Consequences

### Positive

- Consistent with existing dropdowns; maximal reuse.
- Filesystem access isolated and independently testable.
- V2 attachment / symbol references slot behind `FileIndex` and the single
  insertion site.

### Negative

- Touches several call sites in `src/tui/mod.rs`; the key-routing and render
  precedence chains must stay in sync (an existing in-code comment mandates this).

## Implementation Notes

- Add `FILE_MENTION_PREFIX: &str = "@"` and a `TuiCommand::FileMentionDropdown`
  variant; extend `reset_dropdown_selections` and the dismissal-clear path.
- Slot the activation check after the skill branch in
  `key_event_to_tui_command_with_ui` and the matching render chain.
