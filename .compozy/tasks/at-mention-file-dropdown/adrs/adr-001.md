# ADR-001: Scope @-Mention File Dropdown V1

## Status

Accepted

## Date

2026-06-12

## Context

Atelier's TUI composer already provides dropdown completion for `/` commands,
`/agent:`, and `/skill:`. Today users reference files in prompts by typing paths
by hand, which yields mistyped/broken paths and forces recall of deep paths. We
want an `@`-triggered file/folder dropdown.

User decisions from the clarification round:

1. Selecting inserts the **path as text** (mirror the `/` command dropdown) — no
   content attachment, no new run-pipeline semantics.
2. Trigger activates **anywhere in the input** (mid-prompt).
3. Find model: **repo-wide fuzzy search**.
4. Candidate set: **respect `.gitignore`** (untracked-but-not-ignored files
   included; "git-tracked only" was explicitly rejected so brand-new files still
   appear).
5. Primary success signal: **fewer broken/mistyped paths** (accuracy).

Codebase reality: the `/agent:` and `/skill:` dropdowns already solve mid-prompt
token activation (token detector + substring match + token replacement) and
precedence routing; text-insertion and cursor/byte helpers are reusable. Net-new
is a gitignore-aware file walk plus fuzzy matching. There is no fuzzy matcher and
no gitignore-aware walker in dependencies.

Market: OpenAI Codex CLI is the exact analogue (`@` → fuzzy file search →
Tab/Enter inserts the path). Most IDE peers (Claude Code, Cursor, Continue,
Copilot) attach file *content*; `@`-mentions are now table stakes.

A five-advisor council (pragmatic-engineer, architect-advisor,
security-advocate, product-mind, devils-advocate) stress-tested the scope. The
council's majority recommendation was to ship substring + ranking first and defer
true fuzzy. The product owner reviewed that recommendation and **chose to keep
true fuzzy in V1** for the power-user retrieval gesture, accepting the added
matcher dependency. This ADR records that decision.

## Decision

Ship a state-aware `@` file/folder dropdown as a thin discoverability layer that
reuses the existing dropdown machinery:

- **Activation:** mid-prompt via the existing token-detector + precedence
  routing; state-aware (disabled during clarification/approval, like the `/`
  dropdown).
- **Candidate set:** a `.gitignore`-respecting on-disk walk (the `ignore` crate)
  pinned to `working_directory`, including untracked-but-not-ignored files and
  folders; exclude symlinks, `.git/`, and a static secret-name denylist
  (`.env*`, `*.pem`, `*.key`, `id_rsa*`, `.ssh/`, `.aws/`, …).
- **Matching:** **fuzzy subsequence via `nucleo`**, with match-span
  **highlighting** (nucleo returns matched indices).
- **Ranking:** nucleo relevance score, with shallow-path and most-recently-edited
  as boosts/tie-breakers; alphabetical as the final tiebreak.
- **Candidate source is NOT a persistent index:** `nucleo` runs over a **lazy,
  non-persistent walk** built off the render/event path on first `@`, cached for
  the dropdown lifetime and refreshed on re-open. No incremental index, no
  filesystem watcher. (Fuzzy does not require a persistent index, so the
  staleness lifecycle the council flagged is avoided.)
- **Large-repo performance:** off-thread/lazy walk + a result cap with a "refine
  your query" state; `nucleo` is built for interactive matching over large lists.
- **Selection:** insert the **bare path as text** (no `@` sigil left); folders
  get a trailing `/`. Routed through a single `insert_selection(candidate:
  Candidate)` join point, where `Candidate` is a struct (not a bare `String`).
- **Architecture:** the walk + match live in a concrete `FileIndex` struct in a
  non-TUI module; the TUI never touches the filesystem on the draw thread.
- **Keyboard:** parity with the `/` dropdown (Up/Down, Tab/Enter accept, Esc
  dismiss, compact no-match state). Multi-reference works by re-triggering `@`.

## Alternatives Considered

### Alternative 1: Substring matching only (council majority recommendation)

- **Description**: Case-insensitive substring + shallow/recent ranking +
  highlighting; no `nucleo`.
- **Pros**: zero matcher dependency; reuses the `/agent:` filter mechanic;
  satisfies the accuracy metric by construction.
- **Cons**: cannot match non-contiguous abbreviations (`@rcm` →
  `src/runtime/claude.rs`) — the retrieval gesture terminal power users expect
  from fzf/Telescope/Cmd-P.
- **Why not chosen**: the product owner prioritized the fuzzy retrieval feel for
  the target audience; `nucleo` is a small, proven crate (helix-editor), so the
  marginal cost is low.

### Alternative 2: Persistent / incremental watched index

- **Description**: Maintain a long-lived file index kept fresh by a filesystem
  watcher.
- **Pros**: instant matching on very large monorepos without re-walking.
- **Cons**: a staleness lifecycle (branch switch, `git mv`, build artifacts) that
  can surface deleted/moved files and *attack the accuracy goal*; watcher
  portability/edge-case complexity.
- **Why rejected**: `nucleo` over a lazy non-persistent walk is fast enough with
  a result cap; defer a watcher to V2 only if a real large-repo need appears.

### Alternative 3: Content attachment on select

- **Description**: Treat `@file` as a signal to load the file's contents into
  agent context (the Cursor/Claude Code/Continue model).
- **Pros**: richer context; matches IDE peers.
- **Cons**: new run-pipeline semantics; provider coupling; larger scope; moves
  the read action out of the capability sandbox.
- **Why rejected**: the user chose text-insert; keeping selection string-only
  preserves the sandbox as the read boundary. Deferred to V2 behind the same
  `insert_selection`/`Candidate` seam.

## Consequences

### Positive

- Reuses ~90% of the existing dropdown machinery; small, testable V1.
- True fuzzy delivers the fzf-grade retrieval gesture power users expect, plus
  match highlighting for at-a-glance trust.
- Accuracy by construction (only real paths offered).
- Agent-agnostic: a path works regardless of which runtime the prompt routes to.
- Clean V2 seam (structured `Candidate` + single insert join point) for
  attachment and a future watched index without a rewrite.

### Negative

- Adds two dependencies: `ignore` (walk) and `nucleo` (fuzzy).
- More moving parts than a substring-only V1 (ranking blend, result cap).

### Risks

- **First-`@` walk latency on large repos** → off-thread/lazy walk, result cap,
  and a "refine your query" state; `nucleo` is designed for this.
- **Untracked-but-unignored secrets surfaced by name** → static secret-name
  denylist + `working_directory` pin + no symlink-follow + canonicalize-reject
  outside root.
- **Within-session staleness** (file created/renamed mid-session) → refresh on
  dropdown re-open; no persistent index keeps the window small.
- **Discarding the validated reference at selection** → structured `Candidate`
  plus the single `insert_selection` join point.

## Implementation Notes

- Reuse: token detector / precedence (`src/tui/mod.rs` `active_prompt_token`),
  insertion + cursor/byte helpers, dropdown render/keyboard scaffolding, and the
  existing dropdown test patterns.
- Net-new: `FileIndex` (non-TUI module) using the `ignore` crate; `nucleo`
  matching + highlight indices; the `Candidate` struct; ranking blend;
  `insert_selection`; the security denylist and root pinning; result cap.
- Defer to V2: a persistent/watched index, a `FileIndexProvider` trait, content
  attachment, line-range/symbol references, and unioning `extra_read_roots` into
  candidates.
