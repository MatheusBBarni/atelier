# ADR-002: Deliver the full static DAG in V1 (no measurement gate)

## Status

Accepted

## Date

2026-06-14

## Context

ADR-001 adopted the architecture (one `ExecutionGraph` IR + ready-set scheduler,
structural always-on scope arbitration, typed minimal directed edges, durable
`node_id`, fail-closed) and **recommended a phased rollout**: a Phase 0 replay-based
measurement gate, then a scope-derived scheduler, then *data-gated* LLM-authored edges
and output handoff. The product-strategist opportunity scan reached the same
conclusion (a phased hybrid), and an independent critic identified the **output
handoff** (an upstream node's result flowing into a dependent node) as the sharpest
silent-failure surface and proposed a cheap de-risk: replay real prompts from the
existing `.atelier/` event history through the serial executor to measure
decomposition width and handoff prevalence before writing any IR.

After reviewing the scan, the product owner chose to **build the full static DAG in
V1** — including LLM-authored typed directed edges, structure-authorizing whole-plan
approval, and output handoff — prioritizing time-to-differentiated-feature and the
"Strategic Bet / highest-leverage orchestration upgrade" ambition over a blocking
measurement gate. This ADR records that decision and the risks accepted with it.

## Decision

V1 ships the complete council end-state in **one release**:

- **ExecutionGraph IR + single ready-set scheduler** (SingleAgent / ParallelGroup are
  degenerate cases; the all-spawn-at-once path is retired).
- **Structural, always-on scope arbitration** at schedule-time admission, enforced by
  the existing runtime write fence.
- **Typed directed edges** (`data_dependency` | `semantic_gate`) **authored by the
  orchestrator**, including LLM-inferred ordering for cases scope cannot express; with
  cycle detection and a minimal-edge expectation.
- **Structure-authorizing whole-plan approval** — the user approves the proposed graph
  (nodes, edges, concurrency, per-node touch-sets, and handoff sources); in-scope
  write prompts are waived; `RunCommand` and out-of-scope escalations stay gated in
  `normal` mode; `yolo` stays fast.
- **Output handoff** — an upstream node's result is passed as explicit, bounded,
  attributed context to its dependent nodes and recorded as events.
- **Durable opaque `node_id` + event-sourced node lifecycle** (Pending → Ready →
  Running → Succeeded / Failed / Skipped / Cancelled), a `graph_id` sibling to
  `group_id`, and a `ChatLifecycleKey::Node` projection.
- **Fail-closed** mid-graph failure handling (poison/cancel descendants; atomic
  temp+rename writes).

Ships behind the existing `parallel_step_groups` flag (default OFF). The Phase 0
replay-measurement is **retained as a recommended parallel validation and KPI
baseline, not a blocking gate**.

## Alternatives Considered

### Alternative 1: Phased hybrid (recommended by the strategist and the facilitator)

- **Description**: Phase 0 replay-measurement → Phase 1 scope-derived/observed-edge scheduler + cross-runtime placement, instrumented → data-gated LLM edges + handoff hardening; autonomy deferred.
- **Pros**: Hits the KPIs on a vector robust to the decomposition hypothesis; the unverifiable surface (LLM edges + handoff) is committed only after evidence; smallest risk.
- **Cons**: Slower to the fully differentiated capability; splits the work across releases.
- **Why rejected**: The product owner prioritized reaching the differentiated feature now and accepts the risk.

### Alternative 2: Minimal scope-derived scheduler only

- **Description**: IR + ready-set scheduler + edges derived purely from file-scope overlap; never build LLM edges or handoff.
- **Pros**: Provably conflict-free; smallest surface; no silent-missing-edge class.
- **Cons**: Cannot express disjoint-but-ordered cases (interface→impl, edit→test) — which are common and are the feature's correctness value.
- **Why rejected**: Drops the capability that differentiates the feature; the user wants directed ordering in V1.

### Alternative 3: Adjacent-first — cross-provider fan-out

- **Description**: Defer the DAG; upgrade flat groups to place independent nodes across runtimes/providers (+ `/queue` cross-prompt concurrency).
- **Pros**: High KPI-per-effort; structurally hard for single-provider rivals to match.
- **Cons**: Only helps at graph width ≥ 2; doesn't deliver dependency ordering.
- **Why rejected (as V1)**: Kept as a complementary V2 enhancement, not the V1 wedge.

## Consequences

### Positive

- Fastest path to the fully differentiated capability; typed ordering edges + handoff are exactly the seam competitors (Claude Code subagents, LangGraph, CrewAI) lack.
- One coherent release on top of the council's clean architecture.
- The Strategic-Bet foundation (durable `node_id`, event-sourced lifecycle) ships intact, so V2 (resume, re-planning) remains a policy relaxation.

### Negative

- Commits the largest surface in the roadmap before field evidence on decomposition width.
- The output-handoff and missing-edge silent-failure classes are live in V1, and the chosen KPIs cannot directly detect them.

### Risks (ACCEPTED — must be mitigated in the PRD / TechSpec)

- **Missing-edge silent-wrong-result** — *Mitigate*: derive node *independence* structurally from scope (only *ordering* edges are LLM-authored, never independence); cycle detection; the approval enumerates nodes/edges/scopes/handoff sources for informed consent; consider an optional verify/grade node on `data_dependency` edges.
- **Output-handoff corruption (sharpest risk, per critic)** — *Mitigate*: pass upstream results as explicit, bounded, attributed context; record handoff payloads as events; a verify node is the catching mechanism if needed.
- **Amdahl / low decomposition (devils-advocate dissent, preserved)** — *Mitigate*: run the replay-measurement to set the speedup baseline and bias the planner toward wide-shallow graphs; single-agent fallback when no independent fan-out exists.
- **Approval theater** — *Mitigate*: approval authorizes structure with an enumerated, reviewable touch-set; the fence + `RunCommand` gating enforce regardless of what was approved.

## Implementation Notes

- Inherit all of ADR-001's notes (new `DecisionNextStep::Dag` variant; lower SingleAgent/ParallelGroup onto the IR; schedule-time disjointness; `ChatLifecycleKey::Node`; reuse the fence, approval queue, event sourcing, and `WorkflowTarget` ledger).
- Net-new for the full-V1 decision: output-handoff plumbing + handoff events; cycle detection in DAG validation; an approval view that enumerates nodes, edges, per-node scopes, commands, and handoff sources.
