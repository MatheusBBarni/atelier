# ADR-004: Single-agent turn-1 early-abort mechanism

## Status

Accepted

## Date

2026-06-15

## Context

The early-abort is the spine's net-new capability. Codebase reality: the orchestrator doesn't emit a real plan (`plan` is prose), `SingleAgentStepPlan` has no `file_scope` (single-agent runs are `ActionScope::Unrestricted`), and `reason`/`plan` quality is inconsistent. The clarification pause/resume is the proven transport.

## Decision

Hook the early-abort in `drive_run_inner`'s main loop (`app.rs:1858–1871`), **after** the first `Decision` and **before** `handle_orchestrator_decision`. Gate it in only when **all** hold: `status == Continue`; `next_step` is `SingleAgent`; it is the **first orchestrator turn** (`step_count == 0` and no previous results); the run is **not a subtask**; and the **complexity signal** fires — `required_capabilities` includes a write-class tool. On gate-in, build a `GovernanceDecision` (ADR-003) from `reason` (interpreted goal) + `plan` (approach bullets) + `next_step.agent` + a **write-scope rendered from the agent's existing workspace write-roots** (no new per-step `file_scope` needed). Pause into `pending_governance_decision` (`WaitingForUser`); **Accept** resumes via `drive_and_replay`; **Reject** appends an optional redirect to the prompt and re-drives — mirroring clarification. Add a **light orchestrator-prompt instruction** so `reason`/`plan` reliably carry a legible interpreted-goal + approach on turn 1. Non-binding, complexity-gated, feature-flagged.

## Alternatives Considered

### Alternative 1: Add structured `goal_statement` / `file_scope` fields

- **Description**: Machine-readable echo fields on the decision/step plan.
- **Pros**: Most precise and stable.
- **Cons**: Schema change rippling through the decision contract + tests.
- **Why rejected**: Heavier than the V1 echo needs; the prompt-nudge gets legible prose without schema churn.

### Alternative 2: Render raw `reason`/`plan` with no prompt change

- **Description**: Display whatever the orchestrator already emits.
- **Pros**: Zero added surface.
- **Cons**: Echo quality is inconsistent; a vague echo undermines the pause (PRD risk).
- **Why rejected**: The pause is only worth it if the echo is legible.

## Consequences

### Positive

- Catches a misread goal before any write, reusing proven pause/resume; no schema change.

### Negative

- Echo quality depends on prompt adherence; the complexity heuristic (write-capability presence) is coarse.

### Risks

- **Low catch rate** → cut it (Phase-1 proceed-gate ties to the early-abort catch-rate metric).
- **Weak models may not restate well** → degrade gracefully (show whatever `reason`/`plan` carry; never block on echo quality).

## Implementation Notes

Write-scope display reuses the workspace write-roots already on the run context; no `SingleAgentStepPlan` change. Complexity detection lives next to the gate, reading `required_capabilities`.
