# ADR-005: Outcome metric as an event-derived proxy

## Status

Accepted

## Date

2026-06-15

## Context

The PRD's North Star is Trusted Outcome Rate (kept vs reverted), but atelier has **no revert/kept signal** — `record_event` emits action/approval/run events, and there is no concept of a "revert" or a "corrective re-prompt." PRD Q4 chose a derived proxy over new instrumentation or dropping the metric.

## Decision

Compute Trusted Outcome Rate as a **proxy over existing history events**, locally:
- A **governed run** = one that surfaced a governance decision (the early-abort in V1; sibling gates later).
- **Kept** = the governed run reached `Completed` and was **not** followed within the session by an interrupt of that run or a **corrective re-prompt** (heuristic: a user follow-up issued immediately after that redirects/undoes it).
- Counted **against**: early-abort `Reject`, and abort/interrupt after an `Accept`.

Surface it via **`--doctor --json`** as a `DoctorCheck` with a `context` JSON payload, alongside the **directly-measurable calibration metrics** — intervention rate (dual-alarm band), early-abort catch rate, gate precision — which are exact. Label the outcome figure explicitly as a **proxy**.

## Alternatives Considered

### Alternative 1: First-class outcome event kinds

- **Description**: Record `run_kept` / `run_reverted` / `corrective_reprompt` events.
- **Pros**: Precise.
- **Cons**: Needs new instrumentation **and** a UX to capture "revert," which atelier has no concept of.
- **Why rejected**: Disproportionate for V1; can be added later if the proxy proves insufficient.

### Alternative 2: Defer the outcome metric

- **Description**: Ship only calibration metrics in V1.
- **Pros**: Leanest, most honest.
- **Cons**: Drops the PRD's North Star from V1.
- **Why rejected**: The proxy delivers the North Star now, clearly labeled.

## Consequences

### Positive

- Ships the North Star honestly, local-only, with no new instrumentation; exact calibration metrics anchor it.

### Negative

- The proxy is approximate — "corrective re-prompt" is a heuristic and can mislabel.

### Risks

- **Proxy noise** → keep it clearly labeled a proxy, lean on the exact calibration metrics for decisions, and revisit first-class signals if the proxy misleads.

## Implementation Notes

All derivation reads the existing `.atelier` event log; no events leave the machine. Reuse the `DoctorReport`/`DoctorCheck` surface (`src/doctor/mod.rs`).
