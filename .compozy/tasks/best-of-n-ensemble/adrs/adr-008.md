# ADR-008: Deterministic Oracle-Selection with the Judge as Narrator/Tie-Breaker

## Status

Accepted

## Date

2026-06-19

## Context

ADR-001 set the principle "oracle picks, judge narrates." The TechSpec must turn that into a concrete selection function and a judge component boundary. The oracle already yields a per-attempt `GraderVerdict { outcome: Pass|Fail|Skip, exit_code, … }` (`orchestrator/mod.rs:369`). The open question is whether the LLM judge *ranks/selects* among passing attempts (reintroducing position/self-preference/verbosity bias) or whether selection stays deterministic with the judge confined to explanation and tie-breaking.

## Decision

Selection is **deterministic among oracle-passing attempts**; the judge is a **separate, runtime-independent agent step** that narrates and breaks only the ties the oracle cannot.

- **Disqualify:** any attempt whose oracle `outcome == Fail` is removed before the judge runs. If none pass, promote nothing (ADR-003 all-fail path).
- **Deterministic order among survivors:** rank by (1) oracle `outcome` (`Pass` over `Skip`), (2) a stable objective tiebreak (e.g. fewest lint/test warnings, then smaller diff), (3) roster order. The top survivor is the winner whenever this order is decisive.
- **Judge step:** a reviewer-profile agent (`Capability::Read + Review`, no `Edit`) on a runtime chosen **independent of every attempt's runtime** (fallback to the deterministic order if no independent runtime is configurable). It (a) **writes the rationale** shown on the verdict card, grounded in the oracle evidence, and (b) **breaks the tie only** in the no-oracle / all-`Skip` / objective-tie case, with the result flagged **low-confidence** (ADR-003 no-oracle banner). The judge never overrides an oracle-decided winner.
- **Promotion:** the selected winner is promoted via ADR-006 diff-replay regardless of which path (deterministic vs judge-tiebreak) chose it.

## Alternatives Considered

### Alternative 1: Judge ranks all survivors

- **Description**: Always invoke the judge to rank oracle-passing attempts and pick the winner.
- **Pros**: "Smarter" selection; richer reasoning over close calls.
- **Cons**: Reintroduces the exact judge biases (position >10% swing, self-preference, verbosity) the oracle was meant to neutralize; selection authority leaves objective ground.
- **Why rejected**: Contradicts ADR-001; bias surface not worth marginal ranking quality.

### Alternative 2: Judge only on no-oracle/tie (no rationale on the common path)

- **Description**: Invoke the judge solely when the oracle can't decide.
- **Pros**: Cheapest.
- **Cons**: Loses the legible "why it won" rationale on the common oracle-decided path — the product's shareable moment (PRD F5).
- **Why rejected**: The narration is a core value, not optional; keep it on every race.

## Consequences

### Positive

- Selection authority stays on objective test evidence; the judge's bias surface is confined to genuine ties, where it's disclosed as low-confidence.
- The legible rationale is present on every race (the PRD's "tell your friend" moment).
- Runtime-independence structurally excludes the self-preference self-vote.

### Negative

- A judge agent step runs even when selection is deterministic (cost), purely for narration.
- The deterministic tiebreak metric (warnings/diff-size) needs a defined, testable source.

### Risks

- **Judge narration contradicts the deterministic pick** (says B is better but A won on tests) → prompt the judge to *explain the oracle's winner*, not to re-judge; surface oracle evidence as the authority.
- **No independent runtime available** (thin fleet) → deterministic order + a "no independent judge" note; covered in Open Questions.

## Implementation Notes

- The deterministic selector is a pure function `(Vec<AttemptResult with GraderVerdict>) -> (winner, ordered_survivors, decisive: bool)`; the judge step runs after it and only flips the winner when `decisive == false`.
- Reuse the council member-dispatch pattern (`council_member_agent`) for the runtime-independent reviewer step.
