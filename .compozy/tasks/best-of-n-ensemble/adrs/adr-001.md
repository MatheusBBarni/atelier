# ADR-001: Best-of-N V1 — Oracle-Selected Pick-One Over LLM-Judged Synthesize-Merge

## Status

Accepted

## Date

2026-06-19

## Context

atelier integrates multiple agent runtimes (Codex, Claude, Cursor, the zai/`HttpApi` runtime) but every run step executes on exactly one model. The proposed Best-of-N ensemble step would run the *same* instruction across N cross-runtime attempts concurrently and promote a winning patch — directly exploiting the multi-runtime fleet as a quality lever.

The initial direction selected the maximally ambitious shape: the orchestrator **auto-routes** high-stakes steps, an LLM judge **synthesizes a merged** winning patch, attempts vary by **runtime**, and cost posture is **quality-at-any-cost**. A five-advisor council, informed by codebase reconnaissance and market research, stress-tested that shape and converged on a materially different V1.

Key forces:

- **The write-safety invariant.** `validate_action_scope` (`src/actions/mod.rs:455`) hard-denies any write outside an attempt's exact declared `write_files`. `ActionScope` is `Unrestricted | ParallelFileScope`. N attempts writing the *same* files are structurally rejected today; there is **no** production scratch/staging layer (tempfile is test-only).
- **The judge is the documented quality ceiling.** LLM-as-judge exhibits position bias (>10% accuracy swing in pairwise code judging from reordering alone), self-preference bias (a Claude judge over-rates a Claude attempt — and Claude is a first-class runtime), and verbosity bias. Best-of-N's gain is only captured by a *reliable selector*; coverage ≠ selection.
- **A reliable selector already ships.** `self-grading-retry-loop` built an externally-grounded verifier that runs the project's real compile/test/lint and emits a PASS only with cited exit-0 evidence — bias-free, vendor-neutral, position-invariant.
- **Synthesize-merge breaks provenance.** A merged patch is authored by no single attempt, inherits no scope, and must be re-validated from scratch as a new trust boundary — precisely on the highest-stakes change, bypassing the one safety fence.

## Decision

Ship Best-of-N V1 as **oracle-selected pick-one**, opt-in, fail-closed:

1. **Trigger:** explicit, user-invoked `/race` (council-style sentinel routing). Auto-route is deferred.
2. **Fan-out:** N ≤ 3 concurrent attempts, each on a *different* runtime/model, each executing in an isolated per-attempt scratch scope. Introduce exactly one new primitive — `ActionScope::AttemptScope { attempt_id, scratch_dir }` — gated at the existing `validate_action_scope` chokepoint. Reuse the shipped `ExecutionGraph` fan-out scheduler (best-of-N = degenerate graph: N sibling nodes, one logical target, isolated scopes); do not build a separate ensemble scheduler.
3. **Selection (layered, fail-closed gate stack):**
   - **External oracle as hard precondition** — each attempt is graded by the `self-grading-retry-loop` evidence path (real compile/test/lint, exit-0). Attempts that fail are objectively disqualified before any model weighs in.
   - **LLM judge among survivors only** — runs on a runtime *independent* of every attempt's producing runtime (structurally excludes the self-vote); tie-breaks objectively-passing candidates and **narrates** the rationale grounded in the oracle evidence.
   - **No-oracle / all-tie case** — the judge ranks **advisory only**, with explicit low-confidence disclosure, surfacing the top candidate plus the runner-up diff to the user rather than silently auto-applying.
   - **All-fail case** — promote nothing; resolve to a failed run with per-attempt evidence surfaced.
4. **Promotion:** re-derive a `ParallelFileScope` from the winning attempt's *actual* observed write-set, replay its staged diff as a fresh `ApplyPatch` against the real tree through `validate_action_request_with_scope` → `validate_action_scope` and the governance-spine approval gate, union-bounded and fail-closed (a write-set exceeding the derived scope is rejected, never auto-widened).
5. **Lifecycle:** new `RunStepResult` variant + `ChatLifecycleKey`/`ChatItemKind` + projection arm so the race collapses into one evolving chat item (like `Plan`/`GradeLoop`).

## Alternatives Considered

### Alternative 1: LLM judge synthesizes a merged winning patch (the original ambitious choice)

- **Description**: The judge composes a new patch from the best fragments of multiple attempts and promotes it.
- **Pros**: Potentially captures the best of every attempt; the most "intelligent" merge; strongest demo narrative.
- **Cons**: The merged artifact has no producing attempt, no inherited scope, and was compiled/tested by nothing — it rides on the least reliable component (the biased judge) and bypasses the exact-disjoint write fence. LLMs are weakest at splicing diff hunks and may emit hunks that do not apply.
- **Why rejected**: Manufactures an unverified, scope-orphaned artifact precisely on the highest-stakes change. Deferred to V2 strictly as a layer on top of pick-one's promotion path that must still terminate in a re-derived, union-bounded scope through the same fence.

### Alternative 2: Orchestrator auto-routes high-stakes steps (the original trigger choice)

- **Description**: An unattended orchestrator decides when a step is high-stakes enough to spend N× cost, like it convenes council today.
- **Pros**: Zero user friction; the value finds the user; parity with council routing.
- **Cons**: N× token/latency spend decided by an unproven router; misroutes are most expensive exactly where they are least observable; unattended + irreversible + biased-selector is the triad the governance floor exists to stop.
- **Why rejected for V1**: No routing-precision data yet. Deferred to V2 as a config-gated flag (`[ensemble] auto_route`) with trigger predicates, a hard cost cap, and pre-spend disclosure — defaulting conservative, graduating to default-on only after it proves out, exactly as council did.

### Alternative 3: Pure verifiable-coverage (external oracle is the only selector, no LLM judge)

- **Description**: Run N attempts; the test oracle alone picks the survivor; no LLM judge at all.
- **Pros**: Maximally bias-free and simplest; "the harness used *your* tests to pick the winner" is a durable story.
- **Cons**: A large fraction of real coding work has no oracle or a non-discriminating one (refactors, net-new features without tests, all-N-pass ties) — the oracle is a filter, not a total order, and something must still break the tie and explain the result.
- **Why rejected (partially adopted)**: Adopted as the *selection mechanism* wherever the oracle has resolving power. The LLM judge is retained only as the grounded **narrator** and the disclosed advisory tie-breaker for the no-oracle/tie case — never as the authority over an objective result.

## Consequences

### Positive

- The promoted patch always carries intact provenance and flows through the existing, trusted scope fence and approval gate — no new safety path on the highest-stakes change.
- Selection is grounded in objective exit codes, sidestepping every documented LLM-judge bias.
- One new primitive (`AttemptScope`) makes both deferred layers (synthesize-merge, auto-route) cheap later — they reduce to scheduling/selection policy, not new fences.
- Preserves the headline cross-provider differentiator no single-vendor tool can match, while the "tests picked the winner, here's why" verdict is more credible and more shareable than "an AI judge chose."

### Negative

- Less ambitious than the originally requested shape; synthesize-merge and auto-route — both explicitly requested — are pushed to V2.
- The no-oracle/all-tie case still depends on a (disclosed, advisory) LLM ranking, so the bias problem is bounded but not fully eliminated where no tests exist.
- Still requires building the greenfield scratch/staging layer (the unavoidable lift).

### Risks

- **Scratch lifecycle bugs** (leaked dirs, torn promotion) → guaranteed RAII-style cleanup on all exit paths + atomic-or-rolled-back promotion.
- **Scope escape** (winning patch touches files no attempt was scoped to) → re-derive scope from the actual write-set, union-bound, fail-closed at the existing chokepoint.
- **Judge self-preference** → mandatory judge-runtime independence; oracle precedes the judge; judge never overrides an objective result.
- **N× cost on low-value steps** → opt-in only in V1; N cap; pre-spend disclosure.

## Implementation Notes

- Reuse: council sentinel routing (`COUNCIL_WORKFLOW_AGENT_ID`, `orchestrator/mod.rs:10`) and `synthesize_council_decision` (`app/mod.rs:8682`) shapes; `run_parallel_group` / `ExecutionGraph` fan-out; the `reviewer` profile (`Capability::{Review, Verify}`) for the judge node; `self-grading-retry-loop`'s evidence path for the oracle.
- New: `ActionScope::AttemptScope` variant + write redirection in `validate_action_scope`; scratch staging module; `RunStepResult::BestOfNEnsemble` + chat projection arm; `[ensemble]` config block (default off).
