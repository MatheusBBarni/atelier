# ADR-006: Writes-Redirect + Diff-Replay Isolation and Promotion

## Status

Accepted

## Date

2026-06-19

## Context

N attempts must edit the *same* files concurrently without colliding, and exactly one winner must land on the real tree through the existing approval gate. The harness has no scratch/staging layer today, and the exact-disjoint write fence (`validate_action_scope`) forbids overlapping write-sets. Both write executors (`execute_write_file`, `execute_apply_patch`) resolve targets through a single choke point — `resolve_action_path(working_directory, path, extra_roots, …)` (`actions/mod.rs:2000`) — and `apply_unified_diff` is an in-memory hunk patcher (no `git apply`). Tree-copy or git-worktree isolation would be heavier and (for worktrees) couple the feature to git.

## Decision

Isolate by **redirecting writes** to a per-attempt scratch overlay while **reads fall through** to the real tree, then **promote by diff-replay**.

- **New scope:** `ActionScope::AttemptScope { attempt_id, scratch_dir }`. The race runner sets each attempt's `ActionExecutionContext` to carry its `AttemptScope`.
- **Overlay path resolution:** at `resolve_action_path`, a write resolves into `scratch_dir` (`.atelier/race/<run_id>/<attempt_id>/<relpath>`); a read resolves to `scratch_dir/<relpath>` **if it exists there**, else the real working tree. This gives copy-on-write semantics without copying the tree: an attempt sees its own edits, everything else reads through.
- **Grading in scratch:** the oracle runs against the attempt's overlaid view so compile/test/lint reflect that attempt's changes.
- **Promotion (diff-replay):** for the winner, compute the set of files written under `scratch_dir`, build a unified diff of each against the real tree, **re-derive a `ParallelFileScope` from that actual write-set**, and replay it as a fresh `ApplyPatch` through `validate_action_request_with_scope` → `validate_action_scope` + the governance-spine approval gate. Union-bounded, fail-closed: a change outside the re-derived scope is rejected, never auto-widened.
- **Lifecycle:** scratch dirs are created per attempt and removed on every exit path (win, loss, all-fail, cancel, panic) via RAII-style guards; promotion writes are atomic (the existing patcher writes all files after a successful in-memory apply).

## Alternatives Considered

### Alternative 1: Per-attempt full working-tree copy/overlay

- **Description**: Seed each attempt's `working_directory` with a complete copy of the workspace.
- **Pros**: Simplest mental model; reads/writes both just hit the copy.
- **Cons**: Copies the tree N times — expensive and slow on large repos; wasteful when an attempt touches few files.
- **Why rejected**: Cost scales with repo size, not change size; writes-redirect achieves the same isolation lazily.

### Alternative 2: Git worktree per attempt

- **Description**: Create a real git worktree per attempt; promote by applying its diff.
- **Pros**: Strong, battle-tested isolation.
- **Cons**: Requires a git repo; adds worktree create/prune lifecycle; couples a core feature to git; conflicts with non-git workspaces.
- **Why rejected**: Over-couples to git and adds lifecycle complexity for isolation the overlay already provides.

## Consequences

### Positive

- No tree copy: cost scales with the change, not the repo.
- Promotion reuses the existing patcher, scope fence, and approval gate unchanged — the winner is "just another `ApplyPatch`."
- Matches ADR-001's "re-derive scope from the actual write-set" contract precisely.

### Negative

- Overlay read-resolution adds a code path to the hot `resolve_action_path` choke point (must stay correct for reads-after-writes within an attempt).
- Binary files / non-text edits and file deletions/renames need explicit handling in the overlay + diff-replay (note in Open Questions / Risks).

### Risks

- **Read-after-write correctness** inside an attempt → overlay resolves scratch-first for reads; cover with tests.
- **Diff-replay drift** if the real tree changed during the race → re-validate at promotion; fail-closed on hunk-apply failure, surface to the user.
- **Scratch leakage** on crash → RAII guards + a startup sweep of stale `.atelier/race/*` dirs.

## Implementation Notes

- Touch points: `ActionScope` enum, `resolve_action_path` (overlay branch), `ActionExecutionContext` (carry `AttemptScope`), a scratch-lifecycle module, and a promotion helper that builds the winner's diff from `scratch_dir`.
- Deletions/renames represented as overlay tombstones; reflected in the promotion diff.
