# ADR-008: Deterministic MCP testing via an in-repo fake stdio server

## Status

Accepted

## Date

2026-06-15

## Context

The MCP integration speaks JSON-RPC to a spawned subprocess, which is inherently non-deterministic and environment-sensitive. The repo already (a) isolates flaky live-runtime tests behind env vars (`MULTIAGENT_RUN_CODEX_INTEGRATION=1`, etc.), and (b) uses a `fake` runtime to drive deterministic end-to-end app/orchestrator tests. ADR-004 introduces an internal `McpClient` trait as a seam.

## Decision

Three test tiers:
1. **Unit** — exercise the supervisor command handling, `validate_action_request_with_scope` MCP arms, trust-store logic, record-time redaction, and projection against a **mocked `McpClient` trait** (no subprocess).
2. **Deterministic E2E** — ship an **in-repo fake stdio MCP server** (fixtures: one read-only resource, one read-only-annotated tool, one effect tool, one tool with a mutating description to exercise the F6 diff-on-change) that tests spawn over real stdio, validating the real `initialize` handshake and framing.
3. **Live (ignored)** — real published servers (e.g., `@modelcontextprotocol/server-everything`) behind `#[ignore]` + an env var (e.g., `MULTIAGENT_RUN_MCP_INTEGRATION=1`), mirroring the existing live suites.

The PRD's small-model **emission spike** is a separate, explicitly-gated harness (not part of the default suite).

## Alternatives Considered

### Alternative 1: Real reference server in CI

- **Description**: Spawn `server-filesystem`/`server-everything` via `npx` in the default test suite.
- **Pros**: Highest fidelity.
- **Cons**: Requires Node/npx, network/install; exactly the env-sensitive flakiness the repo already warns about.
- **Why rejected**: Non-deterministic CI; kept as the opt-in live tier instead.

### Alternative 2: Mock-only at the client boundary

- **Description**: Never spawn a subprocess; test purely against the mocked trait.
- **Pros**: Fastest, fully deterministic.
- **Cons**: Never exercises real stdio framing or the handshake; integration bugs slip through.
- **Why rejected**: The in-repo fake server adds real-stdio coverage cheaply and deterministically.

## Consequences

### Positive

- Deterministic CI that still exercises real stdio + handshake; optional high-fidelity coverage on demand.

### Negative

- A fixture server to build and maintain.

### Risks

- **Fixture drift** from real-world servers — the `#[ignore]`d live tier is the periodic reality check.

## Implementation Notes

The fake server implements the same wire protocol a real stdio server would; the `McpClient` mock targets the trait from ADR-004. Redaction tests inject a known secret in a tool result and assert it never reaches the on-disk `.atelier/` payload.
