# ADR-001: Externally-grounded auto-verification loop, not an LLM self-grader

## Status

Accepted

## Date

2026-06-15

## Context

The seed idea proposed an automatic "self-grading verify-and-retry loop": after an Edit-capable
agent step reports Completed, route to a grader agent that emits a structured PASS/FAIL verdict,
and on FAIL re-dispatch the same agent with the critique appended, bounded by `max_review_fix_cycles`.

Adversarially-verified research (codebase + market + literature) corrected three premises the seed
rationale rested on, and a five-advisor council (pragmatic-engineer, architect-advisor, product-mind,
devils-advocate, the-thinker) debated four tensions to convergence:

- **The decisive evidence:** LLM self-critique reliably improves output **only when grounded in
  external feedback** (compile/test/lint). Pure self-grade is unreliable and can *degrade* correct
  work (Huang et al. 2310.01798; CRITIC ~54% self-verify; Olausson — human/executable feedback 1.58×
  GPT-4 self-feedback). Self-preference bias means a model passes its own buggy code; unbounded
  refinement accumulates security flaws (2506.11022).
- **Market:** built-in auto-verify is becoming table stakes (Claude Code 2.1, Cursor, Cline); the loop
  is *not* a paywalled capability (CrewAI guardrails ≈ this exact design, free). The only honest edge
  is **external grounding by default + clean grader/implementer separation + bounded, observable cycles**.
- **Codebase:** `max_review_fix_cycles` is already a *live* bound on a **discretionary** reviewer→fixer
  cycle (the real gap is the *automatic* trigger). `AgentResult` has **no machine verdict field**;
  `status` means "how the turn ended," not "correct." The built-in `reviewer` profile (Read/Command/
  Verify, **no Edit**) can already `RunCommand`. Per-step limit checks are duplicated across ~6 methods
  with no shared helper. Council is a hardcoded sentinel (string-equality at 3 sites), not a plugin seam.

## Decision

Build V1 as an **externally-grounded automatic verification loop**, not an LLM self-grader:

1. **Grounding is non-optional.** The grader (the built-in `reviewer`, no Edit) **runs real
   compile/test/lint via `RunCommand`**. A PASS is emittable **only** when a cited external gate
   returns exit 0. The pure-LLM-self-grade path is **cut entirely**.
2. **Trigger + dynamic oracle skip.** Fire after every Edit-capable Completed step (broad, cheap), but
   resolve oracle-existence **dynamically inside the gate**: if an external check yields a pass/fail
   signal, grade; if none exists, **SKIP silently and emit no verdict** — never fabricate a pass
   (no-op-as-pass = false certification) and never punish good work (no-op-as-fail).
3. **Typed, machine-derived verdict.** Add a new verdict record — do **not** overload `AgentResult.status`.
   Two axes: `verified` (deterministic AND of external exit codes, with command + exit code + captured
   output retained as cited evidence) and `correct` (at most an LLM **triage** of concrete failures,
   never the producing agent's own boolean). FAIL payload = structured failures + triage (routes the fixer).
4. **Explicit second branch, defer the registry.** Implement grader dispatch as an explicit branch
   modeled on the council sentinel; **defer** a generic virtual-target registry to a fast-follow
   (rule-of-two: extract once grader + council are both concrete).
5. **Extract the shared per-step-limit helper first.** Consolidate the ~6 duplicated per-step limit
   checks into one helper *before* the grader lands, so the loop reuses the bound instead of adding a
   6th copy; reuse `max_review_fix_cycles` as the cycle bound.
6. **Escalate on exhaustion.** On cycle exhaustion, escalate to the user via `WaitingForUser`
   (accept / retry / abort) — requires new tri-state routing in the resume path.
7. **Render as one evolving chat item** via a new `ChatLifecycleKey` (e.g. `GradedStep`), *not* the
   council `Workflow` key (which deliberately does not collapse).
8. **Default OFF for V1**, with discoverability hints (`--doctor` / first-run / `/config`) and a
   **documented V2 flip criterion**: default-ON wherever an external check exists, once the verdict
   field and escaped-defect data justify it.

## Alternatives Considered

### Alternative 1: Pure LLM self-grader (the original proposal)

- **Description**: Grader LLM emits PASS/FAIL from its judgment of the diff; reuse `AgentResult.verification`.
- **Pros**: No new schema; works even where no tests exist.
- **Cons**: The evidence says ungrounded self-grade is unreliable and degrades correct work; self-preference
  bias passes buggy code; `verification` is self-attested by the producing agent.
- **Why rejected**: Negative expected value without external grounding; unanimous council rejection.

### Alternative 2: Minimal — auto-fire the existing reviewer→fixer cycle on exit codes only

- **Description**: Just make the discretionary reviewer→fixer cycle auto-trigger with a command-exit-code
  gate; no verdict field, no registry (pragmatic-engineer / devils-advocate).
- **Pros**: ~90% of the value for ~10% of the work; reuses live, tested machinery.
- **Cons**: Cannot machine-enforce the locked "correct AND verified" bar without a verdict field;
  overloads `status` (conflates "finished" with "correct"); leaks into history/projection.
- **Why partially adopted**: Reuse the existing path and defer the registry — but a **typed verdict** and
  the **shared limit helper** are retained because they are minimum-correct, expensive-to-reverse choices.

### Alternative 3: Full platform — virtual-target registry + grader sentinel up front

- **Description**: Extract a generic reserved-id→executor registry, migrate council, add grader (architect's maximal).
- **Pros**: Pays down council's string-equality coupling; clean seam for future virtual targets.
- **Cons**: Speculative generality from one real instance + a hypothesis.
- **Why deferred**: Rule-of-two — prove the grader, then extract the registry as an immediate fast-follow.

## Consequences

### Positive

- Ships the one variant the evidence supports (external grounding); avoids the documented degradation mode.
- Reuses live infrastructure (reviewer profile, `max_review_fix_cycles`, `WaitingForUser`).
- A typed verdict gives deterministic retry-gating *and* the legible red→green trust surface.
- Extracting the limit helper removes existing duplication as a side effect.

### Negative

- More than the minimal path: a new verdict record + 3 runtime schema-brief updates, tri-state escalation
  routing, a new `ChatLifecycleKey` + projection arm.
- Default-OFF risks low discovery/adoption until the V2 flip (preserved dissent).

### Risks

- **Self-preference bias** → derived verdict (exit-code-grounded) + grader ≠ producer.
- **Unbounded loops / security drift (2506.11022)** → bounded by `max_review_fix_cycles` + skip-on-no-oracle + convergence.
- **`status` overload** → separate verdict field.
- **6th limit copy** → extract shared helper first.
- **Invisible events** → add the projection arm (the `step_limit_reached` gap is precedent).
- **Step-budget interaction** → decide whether grader sub-steps consume `max_agent_steps` or are accounted separately.
