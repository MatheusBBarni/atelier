# ADR-003: Independence is defined over the producer-family *set* of the working diff, with a loud SKIP when it collapses

## Status

Accepted

## Date

2026-06-19

## Context

ADR-001 defined the diversity rule against a single producer's recorded model
family (per-step provenance). ADR-002 chose `/review` to target the **whole
current uncommitted working diff** rather than the most recent agent step. A
working diff is not produced by one agent: it can mix changes from several agent
steps (potentially different model families) and hand-edits made by the human,
which have **no recorded producer lineage at all**. "Reviewer family ≠ *the*
producer family" is therefore underspecified for this target, and getting it wrong
reintroduces exactly the theater-diversity failure ADR-001 set out to prevent (a
reviewer that shares a family with code in the diff, presented as independent).

## Decision

Define independence over the **set** of producer families that contributed to the
working diff:

1. **Compute the producer-family set.** Union the recorded `model_family` of every
   agent step whose changes are present in the working diff. Hand-edited or
   otherwise unattributable changes contribute an `unknown` marker to the set, not
   a family.
2. **Independence rule.** The chosen reviewer's `model_family` must be **absent
   from the producer-family set**. Prefer any reachable family not in the set.
3. **`unknown` is permissive, not blocking.** Hand-edits (family `unknown`) do not
   by themselves veto a reviewer — a human-authored change has no model lineage to
   collude with. The reviewer must only differ from the *model* families present.
4. **Collapse → SKIP loudly.** If every reachable reviewer family already appears
   in the producer-family set (e.g., only one family is configured, or every
   configured family touched the diff), emit a **visible SKIP** ("no independent
   reviewer available — every configured family contributed to this diff"). Never
   silently downgrade to a same-family reviewer, and never fabricate a pass.
5. **Surface the basis.** The review output names the producer-family set it
   diversified against and the reviewer family chosen, so the user can see *why*
   this reviewer is independent (or why it skipped).

## Alternatives Considered

### Alternative 1: Diff only against the most-recent producer's family

- **Description**: Ignore the set; require the reviewer to differ only from the
  family of the last agent step.
- **Pros**: Simplest; matches ADR-001's per-step framing directly.
- **Cons**: A working diff edited by two families would let the reviewer share a
  family with half the diff while looking independent — the precise theater ADR-001
  forbids.
- **Why rejected**: Reintroduces correlated-blind-spot risk for multi-producer
  diffs.

### Alternative 2: Require the reviewer to differ from *all* families including `unknown`

- **Description**: Treat hand-edits as a family that must also be avoided.
- **Pros**: Maximally conservative.
- **Cons**: Incoherent — `unknown` is not a model lineage, so "differ from unknown"
  has no meaning and would force needless SKIPs on any diff a human touched.
- **Why rejected**: Penalizes human involvement with no independence benefit.

### Alternative 3: Fall back to a same-family reviewer with a "low-independence" label

- **Description**: When the set collapses, still review, but label the result
  low-independence instead of skipping.
- **Pros**: Always returns something.
- **Cons**: Manufactures unearned confidence; a same-family review is the
  configuration the evidence says fails, and labelling does not fix the correlated
  blind spot.
- **Why rejected**: Contradicts ADR-001's "SKIP loudly, never downgrade silently."

## Consequences

### Positive

- The independence guarantee holds for the real target (a multi-author working
  diff), not just a single step.
- Human edits are handled sanely — they neither break the feature nor weaken the
  guarantee.
- The SKIP path is honest and explains itself, which itself teaches users to
  configure a second family.

### Negative

- Requires attributing working-diff hunks back to the agent steps that produced
  them (or marking them `unknown`) — more than reading a single step's provenance.
- Diffs that legitimately span all configured families will SKIP, which can feel
  like the feature "not working" until the user adds a different-family runtime.

### Risks

- **Attribution accuracy** — mapping working-diff lines to producer steps may be
  imperfect; when in doubt, mark `unknown` (permissive) rather than guess a family
  (which could fake independence). *Mitigation*: conservative `unknown` default.
- **Frequent SKIPs for single-family users** — surfaced clearly with guidance to
  add a second family, turning a dead-end into an onboarding nudge.

## Implementation Notes

- Producer-family attribution depends on the provenance fact from ADR-001 being
  recorded per step; the working-diff-to-step mapping is the new piece.
- The producer-family set and the chosen reviewer family should appear in the
  review item header and in the SKIP diagnostic.
