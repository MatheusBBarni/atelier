# ADR-004: `/review` is an app command that runs an opinion-only reviewer over an app-acquired git diff, reusing single-step runtime dispatch

## Status

Accepted

## Date

2026-06-19

## Context

ADR-002 chose an on-request `/review` command over the working diff. The codebase
probe established the concrete machinery:

- App commands are early-return guard handlers in
  `App::submit_prompt_with_source` (`src/app/mod.rs:1934`), e.g.
  `handle_provider_status_command` (`src/app/mod.rs:2235`) — the canonical "do
  async work, record one event, return `Ok(true)`" shape.
- A single agent step runs via `execute_runtime_step(&config, request)`
  (`src/runtime/mod.rs:466`); the council loop is just this called per member.
  `council_member_agent` (`src/app/mod.rs:8602`) shows how to mint an opinion-only
  profile (`tools: Some(vec![])`, capabilities `Read/Challenge/Review`).
- There is **no Rust-side working-diff API**: `src/app/git.rs` only reports a
  `dirty` bool. `git diff` is on the read-only auto-approve allowlist
  (`src/actions/mod.rs:1049`).
- A read-only/opinion-only reviewer never triggers an approval prompt in normal
  mode (`apply_floor_and_trust`, `src/actions/mod.rs:443`).

## Decision

Implement `/review` as a new `AppCommand` whose handler:

1. **Acquires the diff app-side.** Extend `src/app/git.rs` with helpers that run
   `git diff` and `git diff --name-only` via the existing `run_git` primitive. The
   app embeds the unified diff and changed-file list directly into the reviewer's
   prompt. No agent action, no approval gate, fully deterministic.
2. **Runs a single opinion-only reviewer step.** Build a throwaway reviewer
   `AgentProfile` (modeled on `council_member_agent`: `tools: Some(vec![])`,
   capabilities `Read`/`Review`, the reviewer instruction brief) on the
   auto-selected independent runtime (ADR-005), and dispatch it once via
   `execute_runtime_step` — bypassing the full serial council loop and not
   requiring an `OrchestratorDecision`.
3. **Stays advisory.** The reviewer cannot Edit or run commands; findings never
   block or mutate run state. The handler records review events and returns
   `Ok(true)`.

The command is registered once in the `slash_commands.rs` `CATALOG` (which also
feeds the dropdown, help overlay, and unknown-command guidance), with the three
catalog enumeration tests updated.

## Alternatives Considered

### Alternative 1: Reviewer runs `git diff` itself via `RunCommand`

- **Description**: Give the reviewer `Capability::Command` and
  `execute_runtime_step_with_actions` so it fetches the diff (and could run
  `cargo test`).
- **Pros**: Reviewer could gather extra evidence (run tests) before opining.
- **Cons**: More moving parts; non-allowlisted command shapes (pipes, `&&`) hit
  approval prompts, breaking the "no new approval surface" promise; less
  deterministic.
- **Why rejected**: V1 is a semantic review of a diff, not a test runner — the
  deterministic self-grading gate already owns running tests. Opinion-only keeps
  it advisory, prompt-free, and simple.

### Alternative 2: Route through the full `run_council_workflow`

- **Description**: Reuse the serial council loop for the single reviewer.
- **Pros**: Maximal reuse.
- **Cons**: Council needs an `OrchestratorDecision`, runs all preset members
  (all HttpApi in the default preset → no family diversity), and is built for
  multi-member synthesis.
- **Why rejected**: `/review` needs exactly one independently-selected reviewer;
  a single direct `execute_runtime_step` call is simpler and the right primitive.

## Consequences

### Positive

- Minimal new surface: one catalog entry, one handler, two `git.rs` helpers, a
  reviewer-profile builder — all modeled on existing code.
- No new approval surface; advisory by construction.
- Deterministic diff acquisition (app-controlled, not model-controlled).

### Negative

- Embedding a large diff in the prompt has a token cost bounded by diff size; very
  large working trees may need truncation (noted as a risk).
- `git`-absent or non-repo working directories must degrade gracefully (no diff →
  nothing to review).

### Risks

- **Oversized diffs** blow the prompt budget → mitigation: cap embedded diff size
  and report truncation in the review header.
- **`git` unavailable / not a repo** → mitigation: detect via `run_git` returning
  `None` and surface a clear "no working changes to review" message.

## Implementation Notes

- Handler: `async fn handle_review_command(&mut self, prompt: &str) -> Result<bool>`
  in `src/app/mod.rs`, inserted before `reject_unknown_slash_command`.
- Diff helpers in `src/app/git.rs` reusing `run_git`.
- Reviewer profile builder modeled on `council_member_agent` (`src/app/mod.rs:8602`).
