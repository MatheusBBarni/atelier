# ADR-001: V1 Prompt History as Per-Project ↑/↓ Recall Projected from the Event Log

## Status

Accepted

## Date

2026-06-12

## Context

`atelier` persists every submitted prompt as a `prompt_submitted` event in the
append-only per-session log (`.multiagent/sessions/<id>/events.jsonl`, payload
carries `prompt` + `submitted_prompt`). Users repeatedly re-type near-identical
prompts — re-running after a failed step, tweaking one clause of a long
multi-clause goal. We want shell-style ↑/↓ recall of past prompts.

Market research: persisted per-working-directory history with ↑/↓ **and** Ctrl-R
is table stakes (Claude Code, Aider, Codex); Gemini CLI lags (in-memory only).
The multi-line ↑/↓ collision is the **#1 shipped bug** across every competitor
(Claude Code #20328/#63670, Codex #21833, Gemini #4220, Warp #11600).
Secrets-in-history is a cataloged technique (MITRE ATT&CK T1552.003).

Locked user decisions: intent = ↑/↓ recall & reuse; V1 = ↑/↓ cycling only
(no reverse-search, no panel); scope = per-project.

Forces:

- ↑/↓ is already bound on the hottest keypath (multi-line cursor nav, queue
  navigation, four dropdowns) — real collision risk.
- Prompts are already persisted → recall is a **read + UI projection**, not new
  persistence (no schema, no migration, no write path to get wrong).
- Outcomes (files changed, token cost, interrupted/limit-reached) are already
  recorded as events sharing the originating `run_id` — a future differentiator.

## Decision

Ship V1 prompt history as a **read-only projection over the existing event log**
(read across `cwd/.multiagent/sessions/*`, fold `prompt_submitted` payloads),
surfaced through **↑/↓ recall** with:

- **Per-project scope** as the default (glob over this project's sessions).
- **Newest-first (reverse-chronological) ordering** — an explicit product stance
  matching shell muscle memory, named now so a future fuzzy-ranked Ctrl-R does
  not fight the precedent it sets.
- **Collision gate** keyed to the existing soft-wrap boundary in
  `move_input_cursor_vertically` (`src/tui/mod.rs:1259`): history steps only when
  the cursor is on the first/last visual row and no dropdown / queue focus is
  active; multi-line and wrapped editing keep cursor navigation.
- **Draft preservation** (readline "saved line"): the in-progress draft is
  restored when ↓ steps past the newest entry.
- **Consecutive-dedup** and a configurable size cap (`UiConfig.prompt_history_max`).
- **Leading-space-skip**: a prompt beginning with a space is not surfaced in
  recall (the secrets escape hatch), enforced at the recall buffer.
- Loaded once into an in-memory `Vec<String>` on the post-first-render async beat
  used by skill suggestions today (no per-keystroke re-scan).

V1 is framed to users as **"recall recent prompts,"** not "searchable prompt history."

## Alternatives Considered

### Alternative 1: Dedicated `prompt-history.jsonl` written on submit (option B)

- **Description**: Maintain a separate per-project history file appended on every submit.
- **Pros**: Simple linear read; no session traversal needed.
- **Cons**: First user-visible fact authored *outside* the event log → dual-write
  and drift risk; discards the `run_id` link needed for prompt→outcome; duplicates
  data the app already owns.
- **Why rejected**: Violates the event-sourced "render derives from events"
  discipline and forecloses the outcome-metadata differentiator.

### Alternative 2: Global (machine-wide) default scope

- **Description**: One shared history across all projects, like `~/.zsh_history`.
- **Pros**: Matches shell muscle memory; no "empty well" in a fresh repo.
- **Cons**: Interleaves semantically irrelevant prompts from other repos; lowers
  signal for goal-against-a-repo recall.
- **Why rejected**: Per-project is higher-relevance in a dev harness, and demand
  for per-project is evidenced by Codex's open requests (#21202/#12627). The
  empty-well risk is better solved by a fast-follow scope-cycle than by
  surrendering relevance.

### Alternative 3: Ship ↑/↓ + Ctrl-R reverse search together

- **Description**: Include incremental reverse-search in V1.
- **Pros**: Meets the competitor table-stakes bar; answers "find last week's prompt."
- **Cons**: Adds a modal search overlay, fuzzy ranking, match highlighting, and a
  new key-routing precedence slot before the substrate is validated.
- **Why rejected**: ↑/↓ is the unavoidable first half of search and captures the
  high-frequency moment; Ctrl-R is a filter over the same in-memory `Vec` and can
  be a fast-follow with no rework.

## Consequences

### Positive

- Minimal, low-risk surface (~2 `TuiUiState` fields + ~15 lines in
  `move_input_cursor` + 1 async load); data already persisted.
- Captures the highest-frequency friction (re-run / tweak of long prompts) on day one.
- Projection design keeps the door open to Ctrl-R (filter over the `Vec`),
  scope-cycling (reader parameter), and prompt→outcome metadata (`run_id` join)
  with no rework.

### Negative

- Below the competitor table-stakes bar (no search) until the fast-follow lands.
- "Empty well" in a fresh project until scope-cycling exists.
- Leading-space-skip filters the recall buffer only; the prompt remains in the
  durable event log (no redaction).

### Risks

- **Soft-wrap / multi-line ↑/↓ collision** (the #1 competitor bug) → gate on the
  existing boundary logic; ship a dedicated test matrix (recall into a wrapped
  line; cursor up/down across the wrap boundary; draft restore after recall).
- **Wedge becomes a permanent floor** → pre-commit a written trigger to build
  Ctrl-R (e.g. recall reuse-rate or median recall-depth threshold) and instrument
  recall depth + reuse rate from day one.
- **Secrets in recall** → leading-space-skip; document that the underlying JSONL
  is unchanged (perms already `0o600`; `.multiagent/` is gitignored).

## Implementation Notes

- New reader primitive `HistoryStore::list_session_event_paths(root)` — the one
  genuinely new piece, reusable by future Ctrl-R / scope-cycling / outcome views.
- Gate history recall in `move_input_cursor` using the `current_line` /
  `input_len <= width` boundary already computed by `move_input_cursor_vertically`
  (`src/tui/mod.rs:1259`).
- Config in `UiConfig` next to `hide_banner` (`src/config/mod.rs:201`),
  with `RawUiConfig` + merge default (e.g. `prompt_history_max = 200`).
