# ADR-003: Component architecture — dedicated export module over the existing projection

## Status

Accepted

## Date

2026-06-19

## Context

The PRD requires a non-interactive `atelier --export-session` that renders a
session's event log to a redacted Markdown transcript. Codebase exploration
established the seams: `build_session_preview(root, id)` already performs
open → `read_events` → `ChatProjection::rebuild` → `sanitize_chat_item`, returning
`SessionPreview { session_id, items: Vec<ChatItemView> }`; the render helpers
`diff_preview.rs` and `command_summary.rs` are pure functions already folded into
`ChatItemView`; and the crate forbids new packages where a file in an existing
module suffices (YAGNI). The open decision was where the ~150-line orchestration
(read → render → scan → gate → write → audit) lives.

## Decision

1. **Reuse `build_session_preview` as the single read path.** The export performs
   no new log reading or projection; it consumes `SessionPreview.items`. The live
   welcome item and overlays it omits are exactly what an export should exclude.
2. **Markdown serializer → new `src/app/chat/markdown.rs`** (`pub mod markdown;`),
   a sibling of `diff_preview.rs`/`command_summary.rs`. It is a pure
   `SessionPreview` (+ scan results) → `String` function that walks `ChatItemView`
   and its `ChatItemKind`/`ChatLineStyle`/`ChatDetailRef` enums.
3. **Orchestrator → new top-level `src/export.rs` module.** It owns
   `export_session(...)`: resolve the session id (explicit or newest via
   `list_session_summaries(root).first()`), call `build_session_preview`, render
   Markdown, run the secret scan (ADR-004), apply the review gate, write the
   quarantined file, and append the `session_exported` audit event via
   `HistoryStore::open(...).append_event(...)` — never through `App`.
4. **Promote the 0600 writer.** `write_private_file` and
   `set_private_file_permissions` become `pub(crate)` so the out-of-`.atelier`
   quarantine file is written with the same owner-only guarantee, without
   duplicating the primitive.
5. **CLI stays thin.** `run_cli_with` gets a dispatch arm beside `--clean-sessions`
   plus a `confirm_export` helper mirroring `confirm_cleanup`; all logic lives in
   `src/export.rs` so it is unit-testable without the binary.

## Alternatives Considered

### Alternative 1: Orchestrator as a free fn in `src/history/mod.rs`

- **Description**: Add `export_session` next to `clean_sessions`.
- **Pros**: Reuses the private 0600 writer with no visibility change; established
  home for non-interactive whole-session operations.
- **Cons**: Grows `history/mod.rs` and mixes durable-storage concerns with
  rendering, secret scanning, and gate/IO — three responsibilities that are not
  storage.
- **Why rejected**: The user chose a dedicated module; separation of the export
  concern outweighs the one `pub(crate)` visibility change.

### Alternative 2: Whole flow inline in `src/cli.rs`

- **Description**: Put orchestration in the `run_cli_with` dispatch arm.
- **Pros**: Fewest files touched.
- **Cons**: Bloats `cli.rs` with non-CLI logic; hard to unit-test (CLI tests are
  struct-literal + `assert_cmd` against the built binary).
- **Why rejected**: Poor testability and cohesion.

## Consequences

### Positive

- Net-new code is three well-scoped units (serializer, scanner extension,
  orchestrator) plus a thin CLI arm; the risky read/projection path is reused.
- `src/export.rs` is independently unit-testable and easy to locate.
- Single 0600 writer keeps the file-permission guarantee DRY.

### Negative

- One new top-level module and one `pub(crate)` promotion in `history`.
- The serializer must keep pace with new `ChatItemKind` variants (a match arm).

### Risks

- **Projection omits something an export needs** (e.g. a future item kind). →
  the serializer renders unknown kinds via a generic title/body fallback rather
  than dropping them silently.

## Implementation Notes

- `markdown.rs` consumes the already-sanitized items; it must still scrub
  `ChatDetailRef::Inline.content` through the scan before emission.
- `export_session` returns a typed outcome (path, counts, flagged categories) so
  the CLI arm renders user-facing messages and tests assert on structure.
