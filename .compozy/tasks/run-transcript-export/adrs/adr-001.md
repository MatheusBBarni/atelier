# ADR-001: V1 scope — CLI-first redacted session export with tiered, detect-don't-mutate redaction

## Status

Accepted

## Date

2026-06-19

## Context

`atelier` records every run as a durable, event-sourced JSONL log under
`.atelier/sessions/<id>/`. That history is write-only in practice: there is no
way to fold a session into a portable artifact that can leave the machine. The
proposed feature exports a session's log to a redacted, human-readable Markdown
transcript so reviewers can see **what the agent did and why** — change
provenance attached to a PR.

A prior shipped feature (`session-browser-resume`) already built the read path:
`HistoryStore::open` + `read_events`, `ChatProjection::rebuild(events).items()`
(the stated fit point, `projection.rs`), and `build_session_preview` (open →
rebuild → ANSI-sanitize) feeding an off-thread, scrollable read-only preview
modal. So the rendering substrate is ~80% reused — but that reused 80% is the
*safe* part (ephemeral, read-only, local). The net-new 20% — redaction trusted
enough to **persist and distribute** — is the entire hard, dangerous problem.

The forces in tension:

- **Irreversible boundary.** Export crosses local → PR → (possibly public) git.
  A leaked credential in git history can only be rotated, never recalled.
- **Weak existing redaction.** The only secret-stripping today is a write-time
  prefix denylist (`Bearer` + `sk-`/`zai-`/`or-`/`ov-`). It fails open; ~58% of
  real-world leaks are "generic" secrets with no recognizable prefix, and the
  export deliberately **keeps** diffs and command output where those live.
- **Provenance requires keeping the narrative.** Aggressive redaction that
  blanks diffs/commands/reasoning corrupts the very artifact reviewers need.
- **CI scriptability.** A non-interactive path is the point for PR/CI use, but it
  removes the human from the loop.
- **Unproven demand.** Reach/frequency score "Maybe"; the cheap reuse makes a
  build-to-learn wedge viable, but a single false-negative leak detonates trust
  in the whole harness regardless of usage.

A four-advisor council (security-advocate, pragmatic-engineer, product-mind,
devils-advocate) debated scope, the redaction trust model, the export unit, and
whether to build at all. Both core tensions reached partial-concession
convergence; this ADR records the resulting V1 shape.

## Decision

Ship **V1 as a CLI-first, recall-gated, tiered redacted session export**:

1. **Surface — CLI first.** Add `atelier --export-session <id>` as an
   early-return entry point (sibling to `--doctor`/`--print-config`), reusing the
   existing `build_session_preview` fold and serializing the resulting
   `ChatItemView`s to Markdown. **Defer the in-TUI `/export` command to V2**, as a
   thin wrapper over the now-proven serializer plus the existing preview modal.
2. **Unit — whole session by default, scopeable.** Export all runs since the
   session launched, with a `--run <run_id>` / `--last-run` flag to narrow scope
   as a blast-radius control.
3. **Redaction — detect, count, flag; never mutate the narrative.** The scan
   surfaces secrets but does **not** rewrite the kept diffs, commands, or
   reasoning. The one mutation allowed is **wholesale body redaction of
   credential files** (`.env*`, `*.pem`, `id_rsa`/`id_ed25519`, `*.key`,
   `.npmrc`, `.aws/credentials`): replace the body, keep the path. Detection is
   **tiered**:
   - **Deterministic, high-confidence matches** (credential-file bodies; literal
     `AKIA…`/`ghp_…`/`xox…`/PEM headers; `Authorization:` headers;
     `*_TOKEN`/`*_SECRET`/`*_KEY=`; `password=`) — the actionable, low-false-positive class.
   - **Fuzzy/entropy matches** — **advisory only** (highlight-and-warn), never a
     gate, to avoid false-positive noise on git SHAs, base64 blobs, UUIDs, and
     lockfile hashes.
4. **Failure posture — tiered fail-closed.**
   - **Interactive:** a mandatory preview that is a **review surface** — flagged
     count + highlighted matched spans — not a raw scroll. Output is never branded
     "safe"; it is footnoted best-effort with "rotate any credential the agent
     touched."
   - **`--yes` (CI):** **fails closed on deterministic hits** (non-zero exit, no
     file written); override only via an explicit, loudly-logged `--allow-flagged`.
     Fuzzy/entropy hits do **not** block `--yes`.
5. **Egress safety.** Write `0600` to a gitignored quarantine path outside the
   working tree by default (e.g. `.atelier/exports/`); warn if the target is
   inside a git repo or is not gitignored.
6. **Audit.** Append a `session_exported` event to the log.
7. **Validate before claiming "safe."** Measure redaction recall against a
   **seeded canary-secret corpus** before publishing any "safe to share publicly"
   guidance; scope early use to private/internal repos; instrument
   **attach-and-repeat** with pre-committed kill/scale thresholds.

## Alternatives Considered

### Alternative 1: Both CLI + TUI surfaces, polished, in V1 (original proposal)

- **Description**: Ship `--export-session` and an in-TUI `/export` together.
- **Pros**: One launch covers automation and in-flow ergonomics.
- **Cons**: The `/export` half mutates the deliberately-fixed slash-command
  catalog, adds a state to the key-routing precedence chain, and is a second,
  TTY-dependent confirm-gate to build and test — all before the Markdown format
  is validated on a real PR. Doubles the confirm-path test surface and the
  cost of fixing a wrong-first-cut format.
- **Why rejected**: Sequencing CLI → TUI proves the format once, cheaply, where
  the provenance job-to-be-done lives; the TUI becomes a thin V2 follow-on.

### Alternative 2: Full entropy + ruleset scanner as a hard V1 gate, fail-closed on anything flagged

- **Description**: Bundle a Gitleaks/detect-secrets-grade scanner; block any
  export (including `--yes`) when anything is flagged.
- **Pros**: Highest automated coverage; strongest-sounding guarantee.
- **Cons**: Entropy over a transcript that keeps diffs is a false-positive cannon
  (SHAs, base64, UUIDs, lockfile hashes); tuned loose it is theater, tuned tight
  it blocks every export and becomes a flaky merge-blocker in CI; a rotting
  ruleset is a permanent maintenance tax; a green check sells false confidence.
- **Why rejected**: Over-builds and breaks CI. The tiered model keeps the
  deterministic, low-false-positive class as a real gate and demotes the fuzzy
  class to advisory — honest coverage without the rot or the flakiness.

### Alternative 3: Preview-only redaction (extend prefix denylist, lean entirely on the human)

- **Description**: Keep redaction modest; trust the mandatory preview as the sole
  control.
- **Pros**: Minimal build; no scanner to maintain.
- **Cons**: A human skimming a 2,000-line whole-session transcript catches the
  secrets they *expect* (which patterns already catch) and sails past a novel
  high-entropy blob on line 1,847; and `--yes` deletes the human entirely, so the
  only unattended path would have zero checks ("defense in zero").
- **Why rejected**: Fails open on the irreversible boundary precisely where no one
  is watching. File-level redaction + deterministic fail-closed-under-`--yes` are
  cheap and close that gap without mutating the narrative.

### Alternative 4: Prove demand before building anything

- **Description**: Require a real "the diff wasn't enough, I needed this" PR plus
  a measured recall number before writing code.
- **Pros**: Avoids building an unwanted artifact.
- **Cons**: You cannot collect a revealed-preference signal for an artifact that
  cannot yet be attached, reused, or rejected; every interim probe is the
  stated-intent vibe it claims to avoid. The ~80% reuse makes building the
  instrumented wedge the cheapest *true* experiment.
- **Why rejected**: Build-to-learn beats interviewing-the-hypothetical here — but
  the council's safety sequencing (recall measured before public-boundary
  exposure) is adopted, capping the downside the "prove first" view rightly feared.

## Consequences

### Positive

- Delivers a differentiated artifact — **redacted, local-first session export** —
  that ships nowhere else (competitors export with zero redaction, or redact only
  in-cloud on paid tiers and disclaim it).
- Reuses the shipped fold pipeline, so net-new is bounded: a Markdown serializer,
  a tiered redaction pass, the CLI flag, the confirm gate, and one audit event.
- Turns atelier's event log into the AI-audit-trail/AIBOM artifact auditors are
  beginning to require (EU AI Act, California AB 2013).
- The honest, never-"safe" framing plus deterministic fail-closed converts the
  redaction risk into a defensible trust feature rather than a liability.

### Negative

- The in-TUI `/export` ergonomics slip to V2; some users will want it day one.
- A tiered model is more nuanced to document and explain than "we redact secrets."
- Whole-session default produces large transcripts; the `--run` scoping flag is
  the mitigation, not a default.

### Risks

- **False-negative leak (primary).** Mitigations: deterministic fail-closed under
  `--yes`; file-level credential-store redaction; honest review-surface preview;
  quarantine path outside the repo; seeded-corpus recall measurement before any
  "safe to publish" guidance; never brand output "safe."
- **`--allow-flagged` becomes a copy-pasted incantation.** Mitigation: loud
  logging on every use; require it to be explicit (never implied by `--yes`).
- **Low adoption (Maybe/Maybe reach & frequency).** Mitigation: instrument
  attach-and-repeat with pre-committed kill/scale thresholds; cheap reuse caps the
  sunk cost if it shrugs.

## Implementation Notes

- Entry point mirrors `--doctor`/`--print-config` in `src/cli.rs` (clap derive,
  early return, no TUI event loop); obtain a `HistoryStore` via
  `HistoryStore::open(root, session_id)`.
- Reuse `build_session_preview` / `ChatProjection::rebuild(...).items()`; the
  serializer walks `ChatItemView`s (title/summary/body/details) to Markdown.
- Redaction runs at export time over the rendered transcript (defense in depth on
  top of the existing write-time pass); it must DETECT/COUNT/FLAG and only ever
  redact credential-file *bodies* — never edit kept diff/command/reasoning spans.
- ANSI/control sanitization already exists (`sanitize_transcript_text`); apply it.
- `session_exported` is a single `record_event` call.
