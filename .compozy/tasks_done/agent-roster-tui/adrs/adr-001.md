# ADR-001: V1 Mechanism and Scope for the Live-Activity-First Agent Roster

## Status

Accepted — decision item 7 (deferring the per-second ticking/refresh cadence to V2) is amended by [ADR-002](adr-002.md), which brings a bounded ~1 Hz refresh and a first-class `Stalled` state into V1. All other decisions in this ADR remain in force.

## Date

2026-06-12

## Context

The Atelier TUI has an always-on left-sidebar "Agent Roster" (~28% width, `src/tui/mod.rs:1952–2008`) listing every configured agent as three fixed lines (name+status / runtime+model / effort+thinking), ordered orchestrator-first then alphabetically. The sibling `atelier-tui-redesign` effort already landed the theme system and per-agent accent colors.

The user's pain is **scannability**: the roster is hard to parse at a glance in the cramped sidebar, both mid-run (who is working, on what) and at-rest (the lineup). The chosen design direction is **"live-activity-first"** — working agents should dominate the eye and idle agents should recede — across a single (non context-adaptive) layout. Scope is deliberately a **presentation reflow**: no interactivity, no multi-layout switching, no per-agent drill-down.

Three hard constraints shape the mechanism:

1. **Accent colors are positional.** `theme.accent_for(index)` resolves `agent_accents[roster_index % 5]`, and the test `roster_names_carry_same_accents_as_chat` pins each agent's roster color to its chat-transcript color. Physically reordering rows therefore *recolors* agents and severs their identity link to the chat below.
2. **No animation infrastructure.** The TUI repaints discretely; list reorders "snap" rather than slide, which the UX literature (animate reorders < 300ms) flags as disorienting — and that mitigation is infeasible here.
3. **Live state is not joined to rows.** Active-agent/`step_label`/`group_id` live in a separate `AppState.live_steps` vec; agent rows come from `AgentView` carrying only a status string. Elapsed time is not exposed in the public view (the `Instant` is internal).

A five-advisor council (pragmatic-engineer, product-mind, the-thinker, devils-advocate, architect-advisor) debated the mechanism, elapsed-time plumbing, and needs-attention treatment.

## Decision

Ship V1 as a **stable-order, weight-driven reflow** built on a unified app-layer roster view-model:

1. **No row reordering and no duplicate "Active" band.** Canonical order (orchestrator-first, then alphabetical) is preserved as the stable identity spine. Live activity is expressed through **visual weight**: active agents render bold with a row highlight and a live current-step line; idle agents are dimmed and recede.
2. **One allowed exception — pin `NeedsInput`.** An agent waiting on the human (approval/input) is pinned to the top of the list. Blocking work earns position; merely-busy work does not. This is the only state permitted to move a row.
3. **First-class `ActivityState` (`Active | NeedsInput | Idle`).** One enum drives ordering policy, weight, and the state glyph, paired with an icon+label (never color alone, per accessibility guidance and the zero-inline-color CI invariant).
4. **Thin non-duplicating summary header.** A single fixed line above the roster ("▶ 2 working · ⏸ 1 waiting") provides the at-a-glance "what's happening now" landmark without relocating or re-rendering any agent row.
5. **Accent-by-identity decoupling.** Resolve each agent's accent from a stable agent key (its canonical identity), not its render-time row position, and let chat read the same source. This makes the `NeedsInput` pin safe and removes the positional-accent fragility.
6. **Unified roster view-model.** Perform the `live_steps`↔`AgentView` join in the app/projection layer, producing a single `RosterRow { identity, accent, activity, … }`; the renderer stays a pure function of that input.
7. **Coarse elapsed time, minimal plumbing.** Surface the step start timestamp on the joined row and render `now − start` at **whole-second** granularity on **active rows only**. Defer the ticking/animated per-second redraw cadence to V2.

## Alternatives Considered

### Alternative 1: Physically reorder rows active-to-top (the literal "float")

- **Description**: Sort working agents above idle ones each render, htop-style.
- **Pros**: Honors the literal "float to top" phrasing; positional dominance is the strongest hierarchy cue.
- **Cons**: Recolors agents (positional accents) and breaks the pinned chat-identity test; snaps with no animation; destroys spatial memory exactly when cognitive load is highest (mid-run).
- **Why rejected**: Trades a tested correctness invariant and spatial memory for salience that visual weight already delivers. Even the advisors who could make it *legal* (via accent decoupling) judged it not *worth it*.

### Alternative 2: Hybrid sticky "Active" band of duplicated rows

- **Description**: A top band re-rendering the active agents (with accents preserved via decoupling) above the full stable lineup.
- **Pros**: Positional dominance without recoloring; keeps a static reference below.
- **Cons**: Re-renders an agent in two places (fractures "one agent, one identity"); doubles vertical/horizontal pressure at 28% width, truncating the live step text first; still snaps as agents enter/leave the band.
- **Why rejected**: Both original proponents (Architect, Product Mind) dropped it under rebuttal — a thin summary header delivers the at-a-glance signal more cheaply, and weight delivers the dominance in place.

### Alternative 3: Pure render-only reflow, defer all plumbing

- **Description**: Bold/dim rows from existing data only; no app-layer changes; no elapsed; fold needs-attention into generic "active".
- **Pros**: Smallest possible diff; one file; zero regression surface.
- **Cons**: Showing the current step *already* requires the `live_steps` join, so "render-only" is illusory; without elapsed the board can't distinguish "working" from "stuck"; folding needs-attention buries the one event that requires the human, and a parallel boolean is actually more code than one enum.
- **Why rejected**: The join is sunk cost; once paid, a coarse elapsed field and a `NeedsInput` enum variant are cheap and high-value. Pragmatic-engineer conceded the enum is *cheaper* than folding.

## Consequences

### Positive

- Delivers the felt benefit ("my eye finds the live and the blocking first") without breaking accent-identity or spatial memory.
- The `NeedsInput` pin surfaces the only genuinely urgent state at the top of the eye path.
- Accent-by-identity and the unified `RosterRow` view-model leave clean seams for future sort policies, elapsed-tick, or per-agent detail — without touching draw code again.
- Targets a validated, unshipped differentiator (no first-party coding-agent CLI ships an activity-sorted roster; OpenCode RFCs #12463/#15223 remain open).

### Negative

- Crosses from "pure render reflow" into modest app-layer work (accent-by-identity, the join view-model, a start-timestamp field) — a larger diff and test surface than a cosmetic restyle.
- Permanent ownership of one ordering exception (`NeedsInput` pin) and the elapsed formatter.

### Risks

- **Elapsed appears stale without a ticker** — mitigation: during active streaming the render cadence already refreshes frequently, so whole-second elapsed should read as live; confirm in TechSpec whether a bounded refresh is needed (deferred to V2 if not).
- **Reflow regresses existing roster render tests** — mitigation: ≥5 new `TestBackend` snapshot states (idle / single-active / parallel-active / needs-input / narrow-width) plus keeping `roster_names_carry_same_accents_as_chat` green by deriving accent from identity.
- **Low-leverage-polish dissent (devils-advocate)** — mitigation: bounded scope, rides the orchestration moat and the redesign's theme seam (extends, does not duplicate, the redesign which owned color only).

## Implementation Notes

- Build `RosterRow`/`ActivityState` in the app/projection layer (`src/app`), not the renderer; keep `render()` a pure function of the view-model.
- Derive accent from a stable agent key in `AgentView`; repoint chat accents at the same source so `roster_names_carry_same_accents_as_chat` stays meaningful.
- All new styling must use `theme.rs` tokens (CI invariant `colors_live_only_in_theme_module`).
- State must be conveyed by glyph+label, not color alone.
