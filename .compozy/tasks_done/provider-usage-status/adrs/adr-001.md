# ADR-001: Truthful Provider Usage Status Scope

## Status

Accepted

## Date

2026-06-12

## Context

Atelier users want to check Claude and Codex subscription usage from inside Atelier. The refined request is a status command that shows remaining quota, ideally exact quota, through provider integrations.

Repository exploration found no existing Atelier code path for subscription quota, remaining credits, usage limits, or provider usage telemetry. Prior feasibility analysis also found that local Claude, Codex, or CLI session data cannot prove exact subscription quota. Exact quota should only be displayed when a documented provider API or explicit account-linking surface returns it.

Provider quota semantics may differ across consumer subscriptions, API billing usage, model tiers, rate limits, rolling windows, teams, organizations, and enterprise accounts. A single inferred `remainingQuota` field would risk false precision.

## Decision

V1 will scope the feature as a provider usage status command that reports truthful provider state and exact remaining quota only when a supported, documented provider integration returns exact quota data.

The command should report:

- Claude and Codex provider connection state.
- Selected provider and model configuration where available.
- Exact subscription quota only when returned by a documented provider API or explicit account-linking integration.
- First-class unavailable states when exact quota is not exposed by the provider.
- Recent provider errors that help distinguish quota, authentication, billing, rate-limit, and local runtime problems.
- Guidance to official provider account pages when exact quota is unavailable.

The provider integration model should use capability negotiation. Each provider adapter should declare which data classes it supports, such as subscription quota, API billing usage, rate limits, model availability, authentication state, and local runtime health. The UI must preserve provider-native meanings instead of normalizing all values into one combined percentage.

## Alternatives Considered

### Promise exact quota as the baseline behavior

Rejected. Claude and Codex subscription quota may not be exposed through documented provider APIs. Promising exact quota would create a product commitment that may be impossible to satisfy for one or both providers.

### Infer quota from local CLI or session data

Rejected. Local session usage, selected models, recent errors, and CLI configuration can help diagnose status, but they cannot prove account-side subscription quota.

### Scrape provider dashboards or undocumented endpoints

Rejected. Dashboard scraping and undocumented endpoints are fragile, privacy-sensitive, and likely to violate user trust. They also create high maintenance risk when provider UI or internal APIs change.

### Build a broad provider account center in V1

Rejected for V1. A full account center could be valuable later, but it expands scope into account management, historical usage, organization switching, billing diagnostics, and multi-provider administration before the quota capability feasibility is confirmed.

## Consequences

- V1 may not satisfy users who expect exact quota immediately for every provider, but it avoids false precision.
- Unsupported exact quota is a first-class result state, not an error and not an estimate.
- The command can still deliver useful troubleshooting value by showing provider auth, selected model configuration, local runtime health, recent provider errors, and official guidance.
- Provider adapters must model provider-native quota semantics explicitly, including whether data is live, cached, unavailable, or unsupported.
- Account linking introduces security and privacy requirements: explicit consent, least-privilege scopes, revocation, secure local token storage, and redaction of tokens and account identifiers from logs.
- The feature should avoid mixing API billing usage, subscription quota, rate limits, and local runtime health into one ambiguous total.
- Future versions can build on this scope with quota-aware session preflight, provider account center capabilities, historical trends, or workflow-aware budget guardrails.

## Out of Scope for V1

- Undocumented provider endpoints.
- Provider dashboard scraping.
- Inferred subscription quota.
- Combined Claude plus Codex quota totals.
- Team admin billing dashboards.
- Quota forecasting.
- Automatic provider plan recommendations.
