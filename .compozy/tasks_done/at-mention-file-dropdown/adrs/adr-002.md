# ADR-002: Package @-Mention File Dropdown as a Complete Single-Release V1

## Status

Accepted

## Date

2026-06-12

## Context

ADR-001 set the V1 scope and technical direction. During PRD brainstorming three
user-experience decisions were confirmed: folders **insert-and-close** (a folder
is a referenceable value, not a browse target), the inserted text is a **bare
path** (the `@` is consumed on accept), and typing a bare `@` immediately shows
the **most recent/shallow files**.

The remaining product choice was how to **package** V1: ship the complete
experience at once, split it thin→thick across phases, or expand it with extra
discovery affordances. The advisory council established that matched-character
highlighting and relevance ranking are the V1 *trust mechanism*, not optional
polish — which bears directly on whether they can be deferred.

## Decision

Ship V1 as a **single, complete release** containing the full experience: fuzzy
matching, matched-character highlighting, recent/shallow ranking, files and
folders (insert-and-close), bare-path insertion that preserves surrounding text,
the empty-`@` recent-files default, the "No matching files" state, Tab/Enter
acceptance, Esc dismissal, state-aware suppression, and the security guardrails.

Future work (symbol/codemap references, content attachment, a watched index for
very large repositories) is staged as **later phases**, not as a split of V1.

## Alternatives Considered

### Alternative 1: Phased thin→thick

- **Description**: Phase 1 ships a minimal files-only inserter (no highlighting,
  recents, or folders); Phase 2 adds the polish.
- **Pros**: Earliest validation; smallest first surface; de-risks performance.
- **Cons**: The first release lacks the highlighting/recents the council called
  non-negotiable for trust; more release overhead for a small feature.
- **Why rejected**: Defers exactly the affordances that make selection
  trustworthy; the feature is small enough to land cohesively.

### Alternative 2: Discovery-forward V1

- **Description**: Approach A plus richer rows (type/recency indicators), a help
  hint, and prominent recents aimed at newcomers.
- **Pros**: Most welcoming for first-time users.
- **Cons**: Added render complexity and row noise for a table-stakes,
  low-differentiation feature.
- **Why rejected**: Over-investment; marginal discoverability isn't worth the
  extra surface in a terminal row.

## Consequences

### Positive

- Cohesive UX that meets expectations on first ship; highlighting and ranking
  arrive together.
- A single test/release cycle; matches the approved idea.

### Negative

- No incremental user value until the whole V1 lands.
- A slightly larger first change than a thin slice.

### Risks

- Larger scope to land at once → mitigated by heavy reuse of the existing
  dropdown machinery and a tightly bounded feature set.

## Implementation Notes

- V1 content is the union of the idea's Core Features (F1–F8).
- Later phases (see the PRD Phased Rollout): symbol/codemap references, content
  attachment, and a watched index — all built behind the V1 reference seam from
  ADR-001.
