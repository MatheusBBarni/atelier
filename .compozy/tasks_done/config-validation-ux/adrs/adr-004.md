# ADR-004: Shared `util::edit_distance` and additive near-miss config hints

## Status

Accepted

## Date

2026-06-15

## Context

The typo hint ("did you mean `codex`?") must reuse Levenshtein distance, which already exists as a **private** `edit_distance` in `skills/mod.rs:909`. The config module cannot call it without exposing it. Making it `pub` in `skills` would force `config` (a foundational module loaded at startup) to depend on `skills` (a higher-level feature module) — backwards layering. The crate root (`src/lib.rs`) has a flat `pub mod` list and **no existing util module**.

The codebase exploration also identified three existing config-load error sites where a near-miss table name can appear, all reached after `or_insert` creates a phantom entry (`deny_unknown_fields` guards unknown *fields*, not unknown *table names*):

- runtime missing `type` — config/mod.rs:1313 (`[runtimes.codx]` phantom)
- agent references an undefined runtime — config/mod.rs:1411 (`runtime = "codx"`)
- agent missing required field — config/mod.rs:1410/1421 (`[agents.fixr]` phantom)

The PRD confirms the friendly "did you mean `X`?" phrasing and that the hint must be strictly additive (no new failure/warning for configs that load).

## Decision

**Relocate `edit_distance` to a new leaf module `src/util.rs`** (`pub fn edit_distance`), declared `pub mod util;` in `lib.rs`. Both `config` and `skills` import `crate::util::edit_distance`; the private copy in `skills` is removed (its `skill_name_suggestions` keeps its own thresholding).

**Add a shared suggestion helper** `util::suggest_nearby_name(unknown: &str, known: impl Iterator<Item=&str>) -> Option<String>` that returns the closest known name within an edit-distance threshold (`2.max(unknown.len() / 3)`, matching the skills convention), or `None`. A thin formatter yields `"; did you mean \`codex\`?"` or `""`.

**Apply the hint at all three near-miss sites.** The "known" set is the sibling keys already present in the merged config (the four builtin runtimes / eight builtin agents are always present), so the suggestion is self-maintaining with no hardcoded const to drift. The append is purely additive — it only enriches an error that already fires; configs that load successfully are untouched.

## Alternatives Considered

### Alternative 1: Make `edit_distance` `pub` in `skills`

- **Description**: Expose the existing function in place; `config` calls `skills::edit_distance`.
- **Pros**: Smallest diff.
- **Cons**: `config` → `skills` dependency edge is semantically nonsense and inverts layering.
- **Why rejected**: A leaf `util` module costs ~10 lines and avoids the accidental coupling.

### Alternative 2: Duplicate the function in `config`

- **Description**: Copy the ~15-line Levenshtein into `config`.
- **Pros**: No shared module.
- **Cons**: Two copies drift; the project already values single-source helpers.
- **Why rejected**: A shared leaf is strictly better than duplication.

### Alternative 3: Hint only at the runtime-missing-type site

- **Description**: Append the hint at one site.
- **Pros**: Smallest surface.
- **Cons**: Agent-name and undefined-runtime typos keep today's opaque error.
- **Why rejected**: Same helper at three call sites is cheap and strictly additive (see ADR for hint sites in the PRD answers).

## Consequences

### Positive

- `config` and `skills` share one Levenshtein implementation through a neutral leaf; no layering inversion.
- Self-maintaining "known" set (sibling keys) — no const list to keep in sync with builtins.
- Differentiates vs the serde `deny_unknown_fields` baseline, which offers no suggestion.

### Negative

- One new top-level module file (`src/util.rs`) — minimal surface, justified by two consumers.

### Risks

- A suggestion firing on a wild typo → bounded by the edit-distance threshold (only close misses suggest).
- False confidence that typos are fully caught → the hint only augments errors that already fire; the load-clean phantom remains a documented V2 doctor-warning (PRD Non-Goals).

## Implementation Notes

- `suggest_nearby_name` picks the single closest candidate (ties broken by iteration order); returns `None` above threshold so wild typos stay silent.
- Apply at config/mod.rs:1313 (compare runtime id vs sibling runtime keys), :1411 (compare referenced runtime vs runtime keys), :1410/1421 (compare agent id vs sibling agent keys).
