# ADR-001: V1 scope and exit-code contract for scriptable config validation

## Status

Accepted

## Date

2026-06-15

## Context

`atelier --doctor` always exits 0, even when checks report `Error` — `DoctorReport::has_errors()` (doctor/mod.rs:48) exists but is never consulted (cli.rs:156-164). Runtime unavailability never rises above `Warn` (doctor/mod.rs:69-70). Separately, a typo'd config table name (`[runtimes.codx]`) silently creates a phantom entry via `or_insert` (config/mod.rs:1170, 1232) and only later fails with a generic "missing required field", with no near-miss hint. The primary consumer for the fix is CI/CD pipelines that need a reliable exit code to gate on config + runtime health.

A five-advisor council (Pragmatic Engineer, Architect, Product Mind, Devil's Advocate, Thinker) stress-tested the trimmed V1. Two tensions were live: (A) binary vs graduated exit codes; (B) whether elevating an unavailable runtime to `Error` is essential adoption insurance or a correctness hazard that produces false CI failures. Both resolved to precise middles, summarized below.

## Decision

Ship a narrow, additive V1 optimized for the CI/CD consumer:

1. **`--doctor --strict` (opt-in).** Default `--doctor` keeps exiting 0 (non-breaking). `--strict` makes `run_cli` return `Err` (→ `main.rs` exit 1) when the report has any `Error`. The exit code is a pure function of the report's max severity.

2. **Reserved exit-code contract (document now, emit-subset in V1).** Publish `0` = healthy, `1` = ran and found blocking problems, `2` = could-not-evaluate / config invalid. The *only* stable guarantee advertised is **branch on `!= 0`, not `== 1`** (1/2 are reserved, non-exhaustive, not-yet-branchable). V1 emits only what control flow already gives (0 and 1); it does **not** rework `main.rs`'s blanket `exit(1)` to emit a distinct `2`. Docs must not claim V1 returns `2` when it returns `1` (reserved ≠ emitted). The emit-`2` rework must land **before `--doctor --strict` is advertised as the supported CI integration**.

3. **Narrow in-use runtime elevation.** A runtime elevates `Warn → Error` under `--strict` **iff** it is the primary (non-fallback) runtime of an agent the default orchestrator chain resolves **unconditionally** on every prompt-driven run, under the merged `EffectiveConfig`. Exposed as an owned derivation (e.g. `EffectiveConfig::referenced_runtime_ids()` restricted to the unconditional chain), reusing the orchestrator's real resolution path — not a fresh static graph-walk. Council-member runtimes, inactive-preset-only runtimes, and model-fallback runtimes explicitly **stay `Warn`**. A guardrail test fails when a new runtime-reference site appears unclassified, so the elevated set cannot widen silently.

4. **Additive typo hint.** When config load already fails with "missing required field" on a near-miss table name, append "did you mean `<name>`?" using `edit_distance` **relocated to a shared text/util module** (not made `pub` in `skills`, which would invert layering: config-load is foundational, skills is higher-level). Purely additive — valid custom-named entries gain no new warning or failure (proven by regression test). User-facing framing is honest: "better hints on errors that already fire," **not** "typo detection."

5. **Discovery nudge.** Default `--doctor` prints a one-line **stderr** nudge when errors are present (e.g. "N error(s) found; re-run with `--strict` to fail CI"), per clig.dev (hints to stderr; suggest, don't auto-apply). This is the cheapest counter to "an opt-in flag nobody flips."

## Alternatives Considered

### Alternative 1: Graduated exit codes emitted in V1 (0/1/2)

- **Description**: Rework `main.rs`'s error path to emit `2` for config-invalid vs `1` for doctor-found-errors.
- **Pros**: Encodes the real "couldn't-run vs found-problems" split (ESLint/Terraform precedent); first-class static-vs-dynamic distinction.
- **Cons**: Requires a global structured-error refactor for a code with zero consumers today; YAGNI.
- **Why rejected**: Reserving + documenting the contract protects the frozen-API boundary at the cost of a paragraph instead of a global refactor. Deferred, bound to a hard trigger (must precede advertising `--strict` for CI).

### Alternative 2: Binary exit code with no reserved contract

- **Description**: Ship 0/non-zero, decide semantics later.
- **Pros**: Smallest possible change.
- **Cons**: `== 1` consumers harden de-facto reliance (Hyrum's Law) during V1→V2; a later 1→2 split becomes a silent break.
- **Why rejected**: Both engineers conceded the contract granularity must be *reserved and published* now, even if not emitted.

### Alternative 3: Static-graph in-use detection / or defer elevation entirely

- **Description**: Approximate "in-use" by static reachability over agents/presets/council; or drop elevation from V1.
- **Pros**: Static graph is simple; deferral is minimal.
- **Cons**: Static reachability over-approximates dynamic use → false CI failures on never-invoked council/preset runtimes → adopters disable the flag. Deferral forfeits the adoption thesis (strict without elevation is a flag worth ignoring).
- **Why rejected**: The "unconditional chain" definition is the one slice where static and dynamic provably coincide ("absence guarantees next run fails"), closing false-failures by construction while pushing residual error into the cheap (false-pass = today's Warn) direction.

### Alternative 4: Warn-on-any-near-miss or hard-fail typo detection

- **Description**: Emit a hint/error whenever an unknown table name is within edit-distance of a built-in, even when it loads cleanly.
- **Pros**: Catches the dangerous phantom typo (`[agents.fixr]` that loads fine and is silently ignored).
- **Cons**: False positives on legitimately unconventional custom names; a behavior change.
- **Why rejected** (for V1): Deferred to a V2 doctor-surfaced **stderr Warning** with concrete acceptance criteria — the correct severity/home for unknown-key detection — rather than a load-time failure.

## Consequences

### Positive

- `atelier` becomes scriptable/CI-gateable via a stable `!= 0` contract — the point of a non-interactive doctor.
- The strict signal is trustworthy: every elevated runtime is a certain (not probable) failure, so CI won't learn to ignore it.
- Typo hints differentiate vs the serde `deny_unknown_fields` baseline (which offers no near-miss).
- Stays a Quick Win: the gate is ~3 lines on existing machinery; `edit_distance` already exists.
- Config diagnostics grows toward one severity/diagnostic model rather than ad-hoc per-flag exit semantics.

### Negative

- Under-coverage on two conditional paths, shipped behind `Warn` (documented): **model-fallback runtimes** (broken precisely at failover) and **runtimes introduced by a non-selected preset** (validated against one assumed activation state). `--strict` is honestly scoped to "the resolved/effective unconditional chain," not "valid for every preset/failover path."
- Opt-in `--strict` risks low discovery — mitigated by the stderr nudge + dogfooding in atelier's own release CI.

### Risks

- **Resolver/validator drift** (the "unconditional" set silently widens) → mitigated by the new-reference-site guardrail test.
- **False confidence** on typos (V1 cannot catch the load-clean phantom) → mitigated by honest framing (a docs/string check that no V1 text promises "typo detection") + a *committed, specified* V2 phantom-Warning task.

## Implementation Notes

- Gate: consult `report.has_errors()` in the `cli.doctor` branch; return `Err` under `--strict`. Validate `--strict` requires `--doctor` (mirror the existing `--json` bail).
- In-use set: derive from `EffectiveConfig` via the orchestrator's existing agent→runtime resolution; restrict to the unconditional default chain.
- `edit_distance`: move from `skills/mod.rs:909` into a shared module both `config` and `skills` depend on.
- Tests: `assert_cmd` exit-code cases (healthy→0, error+`--strict`→non-zero, error without `--strict`→0); unit tests for in-use elevation (referenced-unavailable→Error, idle/council/fallback→Warn); typo-hint unit tests + the "valid custom name emits nothing new" lock.
