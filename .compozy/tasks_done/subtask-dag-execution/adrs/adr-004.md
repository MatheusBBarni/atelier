# ADR-004: DAG decision schema + ready-set scheduler on the reused parallel executor

## Status

Accepted

## Date

2026-06-15

## Context

The TechSpec must choose how to extend the orchestrator decision schema and the
execution engine. Code facts (verified):

- `DecisionNextStep` is an internally-tagged enum (`#[serde(rename_all="snake_case", tag="kind")]`, `src/orchestrator/mod.rs:85`) gated by `OrchestratorDecision.schema_version` (u32). `normalized_next_step` (`:246`) maps v1→`SingleAgent`, v2→`next_step`; unknown versions bail. `validate_decision_next_step` (`:486`) is an **exhaustive** match.
- `run_parallel_group` (`src/app/mod.rs:2005`) spawns **all** children at once (loop `2060–2112`) and joins via an mpsc `select!` loop; `record_parallel_child_result` (`:2812`) is the per-node completion hook.
- The per-node **write-fence already exists and is enforced** (`validate_action_scope`, `src/actions/mod.rs:219`); `ActionScope::ParallelFileScope(scope)` is plumbed per child at `:2483`.
- `validate_parallel_group_plan` (`src/orchestrator/mod.rs:503`) enforces write-file disjointness **globally across the whole group** (a `BTreeMap<PathBuf, step_label>` collision check).
- `HistoryEvent.schema_version` is hardcoded to 1 and readers reject anything ≠ 1 (`src/history/mod.rs:274`).

## Decision

**Schema.** Add `DecisionNextStep::Dag(ExecutionGraph)` (serialized `kind="dag"`) under a
**new `schema_version 3`** in `normalized_next_step`; the v1 and v2 arms stay
byte-identical (frozen). Add the forced `Dag` arm to `validate_decision_next_step`
calling a new `validate_execution_graph`.

**Plan types.**
- `ExecutionGraph { graph_id, reason, nodes: Vec<ExecutionNode>, edges: Vec<ExecutionEdge> }`.
- `ExecutionNode` mirrors `ParallelChildStepPlan` plus a durable `node_id: String` (validated unique). Whether a node runs commands is derived from its `required_capabilities` (Command) — no new field needed.
- `ExecutionEdge { from: String, to: String, kind: ExecutionEdgeKind }`; `ExecutionEdgeKind { DataDependency, SemanticGate }` (snake_case). **Both kinds gate readiness identically** (a predecessor must be `Completed`); the kind is metadata for the plan view and future fan-in semantics.

**Validation** reuses `validate_parallel_child_step_plan` (per-node agent + scope + edit-needs-write_files) and `validate_parallel_scope_path` (path safety) verbatim, and **adds**: (a) acyclicity; (b) every edge endpoint references an existing `node_id`; (c) `node_id` uniqueness; (d) **relaxed write-disjointness** — writes must be disjoint only among nodes with **no dependency path between them** (the possible-concurrency set), replacing the global collision check.

**Executor.** One **ready-set scheduler** lowers onto the reused parallel machinery. Replace the spawn-all loop with `admit_ready_nodes`, which admits a node when:
1. every predecessor is terminal **and** succeeded — *fail-closed*: any failed/blocked/cancelled predecessor marks the dependent terminal `Skipped`;
2. its `write_files` do not intersect the union of `write_files` of currently spawned-non-terminal nodes;
3. if the node runs commands, **no other node is running** (command-node isolation).

Admission re-runs after the approval gate and after **every** `record_parallel_child_result`. `ParallelChildRuntimeState` gains a `NodeRunState` discriminator (Pending → Running → terminal) because today's two-state `terminal_result` cannot distinguish *planned-not-admitted* from *running*.

**Deadlock invariant (critical).** The scheduler must proactively mark every
never-admittable node terminal (`Skipped`/`Cancelled`) and re-run admission on every
terminal transition, so the join loop (which exits only when all nodes are terminal)
always drains.

**Two-layer write safety.** The scheduler guarantees no two intersecting-write nodes
co-run; the existing per-node fence stays **unchanged** as the runtime backstop (reuse
`ActionScope::ParallelFileScope(node.file_scope)` per node — no change to `src/actions`).

**Result.** Add `RunStepResult::Dag(ExecutionGraphResult)` (typed, modeled on
`ParallelGroupResult`), persisted to history under the forever-deserialize contract.

## Alternatives Considered

### Alternative 1: Widen `schema_version 2` to accept `kind="dag"`
- **Cons**: mutates v2's frozen meaning; complicates the version gate.
- **Why rejected**: a new `schema_version 3` keeps every existing arm and error message stable.

### Alternative 2: A separate executor for the DAG
- **Cons**: duplicates the tokio/mpsc coordination, approval queue, limits, and result synthesis.
- **Why rejected**: ADR-001 mandates one ready-set scheduler; flat groups lower onto it as the 0-edge case.

### Alternative 3: Keep global-across-group write-disjointness
- **Cons**: wrongly rejects valid graphs where sequential dependents share a file.
- **Why rejected**: the DAG's value is exactly sequential-shared-file ordering; disjointness must be concurrency-aware.

### Alternative 4: Free-form LLM mutex edges / widened command allow-list
- **Why rejected**: ADR-001 fixed typed *ordering* edges only; ADR-003 Q2 chose command-node isolation over widening the fence (which would weaken the guarantee).

## Consequences

### Positive
- Minimal new surface; reuses the proven executor, approval queue, limits, and fence.
- Backward-compatible: old `single_agent`/`parallel_group` decisions and events keep deserializing.

### Negative
- The ready-set admission + deadlock invariant is the critical new correctness surface.
- Every existing reader of `terminal_result` must be audited for the new `Pending` (planned-not-admitted) state.
- Command-node isolation reduces concurrency for command-heavy graphs (an accepted trade-off for the guarantee).

### Risks
- **Deadlock** if admission is not re-run on every terminal transition. *Mitigation*: the proactive-terminal invariant above; a watchdog test asserting the loop always drains.
- **Silent mis-routing**: the refutable `let Some(DecisionNextStep::ParallelGroup(..))` patterns (`src/runtime/fake.rs:705`, `src/app/mod.rs:4249`) fall through for `Dag`. *Mitigation*: audit and add explicit `Dag` handling.
- **Test churn**: the fake runtime and decision-building tests assert exact error strings; new validators must add **new distinct** messages, not reword existing ones.

## Implementation Notes

- Gate `schema_version 3` / `kind="dag"` guidance in `build_orchestrator_prompt` on `features.execution_graph && max_parallel_agent_steps > 0` (mirror the existing flat gate).
- Thread `graph_id` through events (see ADR-005).
- `ParallelFileScope` already derives `Ord`, making write-set intersection cheap.
