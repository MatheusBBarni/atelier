# ADR-002: Select Focused Clarification Select Approach

## Status

Accepted

## Date

2026-06-06

## Context

The PRD builds on the approved Clarification Select UI idea. Research showed that OpenCode and Claude Code support structured user questions, while the harness already has an orchestrator-owned Clarifying Question flow. The user clarified that V1 should have no skip action, should always show 2-4 recommended answers plus custom text, should optimize primarily for fewer abandoned waiting runs, and should make any-agent question requests an explicit non-goal.

The product choice was between a focused upgrade to existing clarification behavior, a richer clarification plus audit trail, and a general question tool.

## Decision

The PRD will use the Focused Clarification Select approach.

V1 will upgrade the existing orchestrator Clarifying Question experience into a select-style Input Composer state with 2-4 recommended options and a custom answer option. The operator can answer or interrupt the run. V1 will not include skip, multi-question flows, or any-agent question requests.

## Alternatives Considered

### Alternative 1: Clarification Plus Audit Trail

- **Description**: Pair the select-style question experience with richer Chat and Session History presentation as a larger V1.
- **Pros**: Stronger explainability and easier post-run review.
- **Cons**: Adds scope before proving that the core answer flow reduces abandonment.
- **Why rejected**: The main success criterion is fewer abandoned waiting runs, so the first PRD should prioritize the answer loop over richer review surfaces.

### Alternative 2: General Question Tool

- **Description**: Define a broader capability for user questions that could later be used by any specialized agent.
- **Pros**: More future-proof and closer to broad OpenCode-style tool semantics.
- **Cons**: Conflicts with the selected V1 non-goal and expands the user-facing surface before the simple clarification flow is validated.
- **Why rejected**: The user explicitly selected any-agent questions as an explicit V1 non-goal.

## Consequences

### Positive

- Keeps the PRD focused on the primary outcome: fewer abandoned waiting runs.
- Gives operators a complete answer path without widening the whole interaction model.
- Reduces ambiguity between Clarifying Questions and Action Approval.

### Negative

- Does not solve specialized-agent-originated questions in V1.
- Does not provide skip as a separate answer outcome.
- May require a future product pass if richer audit or any-agent question needs become important.

### Risks

- Operators may still want skip once they encounter unwanted questions. Mitigate by keeping interrupt clearly available.
- Recommended answers may be low quality. Mitigate by preserving custom text as a required option.
- Users may confuse questions with approvals. Mitigate through distinct wording and Chat state.

This ADR records product scope only. Implementation details belong in the future TechSpec.
