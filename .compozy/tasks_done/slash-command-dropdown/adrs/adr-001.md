# ADR-001: Scope Slash Command Dropdown V1

## Status

Accepted

## Date

2026-06-06

## Amendment (2026-06-12)

The fixed V1 command set was expanded from 8 to 10 by an approved scope change
during implementation: `/workflow <prompt>` and `/queue <message>` (alias `/q`)
were added to the catalog. Both shipped as real app commands after this ADR was
written and were already user-visible (`/workflow` in app guidance and the help
overlay; `/queue` handled before unknown-command rejection). Excluding them
would have dropped real commands from the very surfaces the shared catalog
exists to align. The "keep V1 fixed and explicitly defer richer behavior"
principle still holds — no new command *capability* was added, only catalog
coverage of already-shipped commands. See `src/slash_commands.rs` and the
task_02 follow-up notes.

## Context

Atelier's TUI already supports dropdown completion for `/agent:` and `/skill:` tokens with Up/Down navigation and Enter acceptance. Built-in slash command metadata is currently split across TUI help text, README command documentation, and app-level unknown-command error text. This creates drift risk and makes available commands harder for new or occasional users to discover.

External agent CLI products have made slash-command discovery a standard interaction. Claude Code documents typing `/` to list commands and typing letters to filter; Cursor added slash commands run by selecting from a dropdown; Slack uses `/` to open a shortcuts menu in the message composer. The user-selected V1 scope is a minimal discovery dropdown when the user starts typing `/`, with Up/Down navigation included.

The main constraints are:

- The dropdown must not become a full command palette or configurable command system in V1.
- The dropdown must not interfere with literal slash-prefixed input, especially clarification answers such as `/tmp/project`.
- Existing specialized `/agent:` and `/skill:` dropdowns must keep their behavior.
- Command metadata must not become another stale hardcoded list.

## Decision

Build V1 as a thin, state-aware slash-command discovery dropdown for the TUI composer.

V1 will:

- Show matching command names and short descriptions when the user types `/` in a safe top-level command position.
- Support Up/Down navigation, Enter acceptance, Escape dismissal, and raw-input preservation.
- Use a narrow command metadata source for built-in commands and prompt prefixes so dropdown rows, help text, and unknown-command guidance can stay aligned.
- Reuse the existing TUI dropdown interaction model where practical.
- Keep command execution ownership unchanged: TUI-local commands remain TUI-owned, app commands remain app-owned, and `/agent:` plus `/skill:` remain prompt prefixes.
- Avoid activation while the app is waiting for clarification or approval input.

## Alternatives Considered

### Alternative 1: Hardcoded Local Dropdown

- **Description**: Add a local list of command names and descriptions only inside `src/tui/mod.rs`.
- **Pros**: Fastest implementation and smallest immediate code change.
- **Cons**: Adds another command source of truth on top of README, help, and app error text.
- **Why rejected**: New users will treat the dropdown as canonical; stale command metadata would be worse than hidden commands.

### Alternative 2: Full Command Palette Platform

- **Description**: Build an extensible command palette that supports configurable project/user commands, categories, dynamic availability, aliases, and richer command execution.
- **Pros**: Stronger long-term platform and closer to mature competitor surfaces.
- **Cons**: Expands scope beyond the requested discovery dropdown and risks delaying a small usability win.
- **Why rejected**: V1 should validate slash-command discovery first and avoid coupling this feature to broader command extensibility.

### Alternative 3: Defer Dropdown

- **Description**: Keep command discovery in README/help/error text only.
- **Pros**: No implementation risk and no chance of input stealing.
- **Cons**: Leaves slash commands hidden at the moment users need them and falls behind current agent CLI expectations.
- **Why rejected**: Existing `/agent:` and `/skill:` dropdown mechanics make a scoped V1 feasible, and market expectations now favor in-composer discovery.

## Consequences

### Positive

- Improves command discovery for new and occasional users at the exact point of use.
- Reduces unknown slash-command submissions.
- Creates a narrow metadata seam that can reduce help/error drift without requiring a full command platform.
- Reuses an existing interaction pattern, which lowers implementation and learning risk.

### Negative

- Adds another dropdown mode to composer key handling.
- Up/Down behavior will intentionally switch from cursor movement to selection while the dropdown is active.
- Requires careful truncation and layout work because command descriptions are longer than agent or skill rows.

### Risks

- **Input theft**: Slash is common in paths, URLs, regexes, and literal answers. Mitigation: trigger only in safe command positions, never mutate input until Enter acceptance, and support Escape/backspace dismissal.
- **Metadata drift**: A stale menu can mislead users. Mitigation: use a narrow shared metadata source rather than a separate TUI-only list.
- **Prefix conflict**: General `/` suggestions could mask `/agent:` or `/skill:` suggestions. Mitigation: preserve specialized dropdown precedence once those prefixes are active.
- **State confusion**: Clarification answers can start with `/`. Mitigation: disable discovery while waiting for user clarification or approval.

## Implementation Notes

- Start with built-in commands and prompt-prefix entries: `/help`, `/goal`, `/goal clear`, `/config`, `/subtask <agent> <task>`, `/agent:<name>`, `/skill:<name>`, and `/reload:skills`.
- Treat the dropdown as autocomplete, not execution. Accepting a suggestion inserts or completes the command text; normal submission still follows existing command handling.
- Keep V2 candidates out of scope: user-defined commands, fuzzy ranking, command categories, disabled reasons, aliases, recent-command ranking, and full palette mode.
- Add focused tests for render/filter/navigation/acceptance, raw-input preservation, specialized prefix precedence, and no activation during clarification input.
