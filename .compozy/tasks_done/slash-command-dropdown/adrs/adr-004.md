# ADR-004: Scope Slash Dropdown Activation And Keyboard Semantics

## Status

Accepted

## Date

2026-06-06

## Context

The new slash-command dropdown must reduce invalid command submissions without stealing normal text input. Existing `/agent:` and `/skill:` dropdowns use token-based matching and can activate mid-prompt. The new command dropdown targets top-level command discovery and must avoid confusion with paths, URLs, clarification answers, approvals, and existing specialized dropdowns.

The PRD also requires a compact no-match state, Tab and Enter acceptance, text-only insertion, and the same visual approach as the current agent and skill dropdowns.

## Decision

Activate the new slash-command dropdown only when the active token begins at the start of the input.

The dropdown will:

- Stay disabled when `pending_approval` is present or the run state is `WaitingForUser`.
- Preserve existing `/agent:` and `/skill:` dropdown precedence once those prefixes are active.
- Insert accepted command text only, without submitting.
- Treat both `Tab` and `Enter` as acceptance keys when a suggestion is selected.
- Insert `/agent:` and `/skill:` prefixes in a way that lets the existing specialized dropdowns take over immediately.
- Show a compact "No commands found" empty state when no suggestions match.
- Trap `Enter` while the no-match empty state is visible, keeping the user in the dropdown until they edit the text or dismiss it.

## Alternatives Considered

### Alternative 1: Match Commands After Whitespace

- **Description**: Allow command dropdown activation at the start of input or after whitespace, matching `/agent:` and `/skill:` token behavior.
- **Pros**: Reuses existing token behavior and supports mid-prompt command discovery.
- **Cons**: Increases chances of activating on paths, URLs, and literal slash text inside prompts.
- **Why rejected**: V1 is top-level command discovery, not inline command composition.

### Alternative 2: Allow Raw Enter On No Match

- **Description**: Let `Enter` submit the raw unmatched slash input and rely on app unknown-command guidance.
- **Pros**: Preserves normal submission behavior and app-level guidance.
- **Cons**: Allows the exact invalid submission the feature is meant to prevent.
- **Why rejected**: The selected product approach prioritizes reducing unknown-command submissions before they reach the app.

### Alternative 3: Auto-Submit Accepted No-Argument Commands

- **Description**: Accepting `/help` or `/config` from the dropdown would immediately submit/execute the command.
- **Pros**: Faster for common no-argument commands.
- **Cons**: Violates the PRD requirement that acceptance inserts text only and never auto-submits.
- **Why rejected**: V1 must preserve user control and avoid accidental execution.

## Consequences

### Positive

- Keeps slash-command discovery focused on top-level commands.
- Reduces accidental unknown-command submissions.
- Preserves existing agent and skill completion behavior.
- Avoids command execution surprises.

### Negative

- Users cannot invoke command discovery mid-prompt.
- No-match `Enter` trapping may feel stricter than normal text input.
- Implementation needs a distinct command dropdown state because no-match rows still render without selectable suggestions.

### Risks

- **Overly strict activation**: Some users may expect `/` discovery after whitespace. Mitigation: document this as V1 scope and revisit with usage evidence.
- **No-match trapping confusion**: Users may not know how to leave the empty state. Mitigation: keep Escape and editing behavior obvious in tests and UI copy.
- **Prefix handoff bug**: Accepting `/agent:` or `/skill:` must not submit or suppress the existing dropdowns. Mitigation: add focused handoff tests.

## Implementation Notes

- Add a command dropdown state and selection index alongside existing agent and skill dropdown state.
- Evaluate dropdown precedence as help modal, agent dropdown, skill dropdown, command dropdown, then normal input handling.
- Reuse char-index helpers for insertion and cursor movement.
- Ensure no app event is dispatched when accepting a command suggestion.
