# ADR-008: Lifecycle events as additive string-kinds + self-healing metadata cache

## Status

Accepted

## Date

2026-06-15

## Context

ADR-002 requires writing a terminal `run_interrupted` and a `session_resumed` boundary event on resume, and treating `metadata.json` `{goal, outcome}` as a derived, self-healing cache. The codebase shapes *how* cheaply this can be done:

- `HistoryEvent` (src/history/mod.rs:12) is a **struct** with `kind: String` + `payload: serde_json::Value`, not a Rust enum. New event types are new `kind` strings — **no enum variant, no `schema_version` bump**. `read_events_from_path` rejects `schema_version != 1`, so the version must stay `1`.
- `ChatProjection::apply_history_event` (src/app/chat/projection.rs:58) matches on `event.kind`; unknown kinds hit `_ => {}` (silent no-op). `run_interrupted` is already emitted in some paths but has no explicit fold handler.
- `SessionMetadata` (src/history/mod.rs:76) is written **once** at `create`; there is no update path, and it lacks `goal`/`outcome`.
- Run outcome is already in per-run records (`.atelier/runs/<run_id>.json`, `state: RunState`) and in the `session_ended` event payload (`run_state`).

## Decision

1. **Model the new lifecycle events as additive string-kinds** (`run_interrupted`, `session_resumed`) with JSON payloads — keeping `schema_version = 1`. Backward compatibility (ADR-003) is preserved because old logs simply never contain these kinds. Payloads:
   - `run_interrupted`: `{ run_id, prior_state }` — closes a dangling run.
   - `session_resumed`: `{ resumed_at, cwd, head_sha, dirty, prior_end_state, approval_mode, prior_tail_hash }` — the tamper-evident resume boundary (ADR-002/004/007).
2. **Add explicit projection handlers** for both kinds: `run_interrupted` renders the dangling run as interrupted; `session_resumed` renders a visible "Resumed" divider in the transcript. Adding handlers (vs relying on `_ => {}`) is required so replay is faithful and the resume boundary is visible.
3. **Extend `SessionMetadata`** with `goal: Option<String>` and `outcome: Option<String>`, both `#[serde(default)]` (old metadata reads back fine). Treat them as a **derived cache**: the authoritative source is the event log. Provide a self-healing read-modify-write that recomputes `goal`/`outcome` by folding the log (a) when the browser reads a session whose cache is missing/stale, and (b) at the points goal/outcome change in a live session (`/goal` set/clear; run reaching a terminal state). On any cache/log disagreement, the log wins and the cache is rewritten.
4. **Add `RunState::is_terminal()`** to replace the scattered `matches!(.., Completed | Failed | Interrupted | LimitReached)` checks and to drive dangling-run detection on open.

## Alternatives Considered

### Alternative 1: Convert `HistoryEvent` to a typed enum

- **Description**: Replace the string-kind + `Value` payload with a Rust enum of event variants.
- **Pros**: Compile-time exhaustiveness on event handling.
- **Cons**: Massive change to ~300 call sites and serialization; breaks the additive-by-construction backward-compat story.
- **Why rejected**: Out of scope; the string-kind model is what makes new events cheap and old logs forward-compatible.

### Alternative 2: Make `metadata.json` authoritative for goal/outcome

- **Description**: Write goal/outcome to metadata as the source of truth.
- **Pros**: List rendering reads one small file.
- **Cons**: A crash between the metadata write and the log write permanently desyncs the list from the transcript.
- **Why rejected**: ADR-002 mandates the log as source of truth; the cache must be self-healing, not authoritative.

## Consequences

### Positive

- New events are purely additive; no schema bump, old logs still fold.
- List rendering is cheap (read small metadata) but can never permanently lie (self-heals from the log).
- `is_terminal()` removes duplication and centralizes dangling-run detection.

### Negative

- Two write points must keep the cache fresh; the self-heal path adds a fold on first browse of a stale session.

### Risks

- A new event kind added elsewhere without a fold handler silently no-ops. *Mitigation:* projection fold tests over representative multi-kind fixtures (including the new kinds).

## Implementation Notes

The label shown in the picker is `goal` if set, else the session's first `prompt_submitted` payload (mirrors `project_prompt_history`'s extraction), else timestamp+outcome. Outcome derives from the last `session_ended`/terminal run state during the fold.
