# ADR-003: Production replay fold as a maintained schema-compatibility contract

## Status

Accepted

## Date

2026-06-15

## Context

`ChatProjection::rebuild(&[HistoryEvent]) -> Self` exists but is **test-only** today; production builds the chat incrementally via `apply_history_event()` and never folds a whole log it didn't just write. The event-sourcing spine the system is built on is therefore **never replayed in production**.

Browse and Resume both require folding a stored log into chat. The moment that ships, the fold becomes **load-bearing**: every event variant atelier has ever emitted must remain replayable, or be explicitly upcast, for the life of the product. The Architect's central point: this is a permanent commitment that must be made *intentionally*, not absorbed accidentally through a feature that looks like UI.

Separately, adopting a different session at runtime is risky if done by piecemeal field mutation on `App` (which owns `HistoryStore` by value): a partial reset can strand a pending approval/clarification modal, leak prior-session state over the watch channel, or leave the one-active-run guard inconsistent.

## Decision

1. **Promote the fold to a production path** and treat backward replay-compatibility as a **maintained contract**. Old logs must keep folding; event-schema changes use **upcasting** (transform old versions to current on read) or versioned handlers. `serde` defaults / ignore-unknown cover only additive/syntactic drift — not semantic drift (renamed meaning, retired variant), which requires explicit upcasting.
2. **Validate at the boundary.** Add `HistoryStore::open(root, session_id)` that checks `schema_version` and **fails loud** on an unsupported/un-upcastable log, so an invalid session is unconstructible (invalid states unrepresentable) and nothing downstream sees a raw/stale event.
3. **Atomic session adoption.** Build a fresh, fully-replayed **typed session-state value** (opened store + folded projection + derived `session_goal`/`run_state` + pending-modal/queue/poller state) **off-thread** using the existing poller pattern, then perform **one atomic swap + one watch broadcast**. No piecemeal in-place field mutation.

## Alternatives Considered

### Alternative 1: Keep the fold test-only / never replay

- **Description**: Status quo; no browse/resume.
- **Pros**: No schema-discipline commitment.
- **Cons**: The event-sourcing spine remains dead weight; the feature is impossible.
- **Why rejected**: The feature's entire value is replaying the spine.

### Alternative 2: Piecemeal in-place rebind of `App` fields

- **Description**: Reassign `history`, wipe/refold projection, re-seed goal/run_state field-by-field.
- **Pros**: No new type.
- **Cons**: Silent partial-reset surface that grows with every future session-scoped field; strands modals; leaks prior state.
- **Why rejected**: A latent bug farm; the grouped atomic swap removes the whole class.

## Consequences

### Positive

- The spine is finally exercised in production with a clear validation seam.
- Invalid/incompatible sessions cannot be silently adopted.
- No torn or half-swapped state is ever observable by the UI.

### Negative

- A real, permanent schema-evolution discipline (intentional debt, recorded here).

### Risks

- **Unresolved nuance (T3):** whether the session boundary is *enforced* — a named `active_session` handle threaded through `App`, or a compile/test-time exhaustiveness guard (in the spirit of the existing `colors_live_only_in_theme_module` test) over a grouped struct owned by `App`. Both council positions agree on the atomic-swap mechanism; the enforcement degree is **left to the TechSpec**.

## Implementation Notes

The `open()`/replay boundary is also the natural emission point for the `run_interrupted` + `session_resumed` events (ADR-002). Add production-grade test coverage for `rebuild` on logs it did not just write (legacy/old-schema fixtures).
