# ADR-005: Product approach — recovery-first, phased delivery

## Status

Accepted

## Date

2026-06-15

## Context

The idea phase locked the V1 shape (browse + read-only preview + Resume; fuzzy search deferred) and the resume semantics (append-in-place, reconcile-to-Idle, full safety model). The PRD phase must choose how to *deliver and emphasize* that scope. PRD research added decisive evidence:

- The read-only transcript preview is the **trust-verification mechanism** — the #1 documented resume complaint is "the AI claims context the user can't see," so the read path carries standalone value (audit + verification) before any write happens.
- **Read-only-first ("shadow mode") is a recognized de-risk pattern**; activating the production replay fold (ADR-003) is the riskiest change, and shipping it as a read-only path first validates session listing/parsing/folding before the write path goes live.
- The user selected **browse-first, resume fast-follow** phasing, full-transcript re-render on resume, multi-entry discoverability, a collision-free trigger key, and first-prompt fallback labels.

Three product approaches were considered: (A) recovery-first phased, (B) audit-forward workspace, (C) minimal recovery.

## Decision

Adopt **Approach A — recovery-first, phased**:

- **Phase 1 (MVP):** session picker (newest-first; label = goal or first user prompt; timestamp; run outcome) + read-only transcript preview. Read path only; zero state mutation. Delivers the auditor use case and the trust-verification view, and de-risks the production fold.
- **Phase 2:** Resume — re-adopt the session, re-render the full prior transcript, append-in-place, write lifecycle events, apply the drift-safe capability model. Delivers the crash-recovery anchor.
- **Phase 3 (deferred):** cross-session fuzzy/content search & audit.

Each phase is the smallest increment that delivers user value, with explicit gates between phases.

## Alternatives Considered

### Alternative 1: Audit-forward workspace (B)

- **Description**: Same phasing, but a richer Phase 1 read experience (more metadata, outcome filters, preview navigation) as a standalone audit hub.
- **Pros**: Stronger standalone Phase 1; positions atelier as a durable workspace.
- **Cons**: Read-side scope creep; slower to the anchor; overlaps the deferred Phase 3 search work.
- **Why rejected**: Over-invests in the read side before the crash-recovery anchor ships; risks blurring the line with deferred search.

### Alternative 2: Minimal recovery (C)

- **Description**: Thinnest find→preview→resume for recent sessions; defer discoverability polish and rich columns.
- **Pros**: Fastest, leanest, lowest pre-data commitment.
- **Cons**: Weak discoverability (the documented CLI failure mode); thin audit value.
- **Why rejected**: Walks back the multi-entry discoverability decision the user made; discoverability is too load-bearing to defer.

## Consequences

### Positive

- Riskiest change (production fold) ships first as a read-only, reversible path.
- Phase 1 has standalone value (audit + trust verification), so the effort de-risks even if Phase 2 slips.
- Clean phase gates make progress legible and instrumentable.

### Negative

- The crash-recovery anchor (the stated primary driver) is not delivered until Phase 2.

### Risks

- Phase 1 read-only could be perceived as "incomplete" without resume. *Mitigation:* ship Phase 2 as the immediate fast-follow; frame Phase 1 explicitly as browse/audit.
