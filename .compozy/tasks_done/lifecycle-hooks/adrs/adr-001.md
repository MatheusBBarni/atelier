# ADR-001: V1 ships cross-runtime observer hooks with a decision-first payload contract; blocking veto deferred to V2

## Status

Accepted

## Date

2026-06-15

## Context

`atelier` is an event-sourced terminal harness that routes prompts through an orchestrator over pluggable runtimes (Codex, Claude, Cursor, zai, fake). Every lifecycle event already funnels through a single write path (`record_event_with_group`, `src/app/mod.rs:4215`) into durable `.atelier/` history; the chat UI is a projection of that stream.

The idea proposes a `[hooks.<event>]` config mapping lifecycle events to shell commands that receive the event payload as JSON on stdin, in two tiers: (1) fire-and-forget observers (notify/audit/lint) and (2) blocking PreAction "veto" hooks (policy-as-code). The user pre-selected an observer-only V1 anchored on desktop-notify-on-approval, with reduced `WaitingForUser` idle time as the success signal.

Market research changed the calculus: **Claude Code, Cursor, and Codex CLI have all already shipped this exact mechanism plus desktop notifications** — events → shell → JSON-on-stdin → block-via-exit-2/decision-JSON is now a de-facto standard. The hook mechanism and the notify use-case are **parity, not differentiation**. atelier's only genuine edges are (a) **runtime portability** — it sits above `RuntimeKind`, so one config governs all runtimes uniformly, whereas every competitor's hooks are a per-vendor silo — and (b) **event-sourcing makes audit inherent**. Enterprise demand corroborates the governance angle: Deloitte (Apr 2026, 3,235 leaders) finds only 21% have mature agent governance, with the #1 named gap being "audit trails that capture the full chain of agent actions"; Gartner (Jun 2025) projects >40% of agentic-AI projects canceled by 2027, partly from inadequate risk controls.

A five-advisor council (pragmatic-engineer, architect-advisor, security-advocate, product-mind, devils-advocate) debated the V1 scope across two rounds and converged.

## Decision

V1 ships the **observer tier only**, reshaped from the original framing:

1. **Flagship = uniform cross-runtime AUDIT, not notify.** One `[hooks.*]` config emits a normalized, versioned event/action shape **identically across Codex / Claude / Cursor / zai**. This is the structurally-hard-to-copy job (a single-vendor competitor cannot follow a runtime-switching user) and maps directly to the #1 documented market gap.
2. **Decision-first payload schema is the load-bearing V1 work.** The cross-runtime action/event payload contract is designed so the V2 blocking veto adds a *return field*, not a redesign — deliberately avoiding "schema capture" by the trivial notify case.
3. **Notify is retained as a minimal slot, demoted from flagship.** Unattended *push* on `approval_requested` / `clarification_requested` / the terminal trio (`run_completed` / `run_failed` / `run_limit_reached`) is kept because push ≠ pull, but it is not the anchor.
4. **`atelier events --follow` ships alongside** — a stable JSON stream over the existing `.atelier/` JSONL — as the cheap pull-based observability path (DIY audit/lint sidecars), so the hook dispatcher only owns the turnkey / uniform / push jobs it uniquely justifies.
5. **Architecture: hooks are an effectful, replay-suppressed sink on a dedicated OFF-funnel dispatcher** (a bounded channel drained by a long-lived task reusing the existing `tokio` `Command` + `kill_on_drop` + `select!`-timeout idiom), **not** an inline spawn at `record_event_with_group` (which runs per `runtime_stream_delta` token — inline spawn would be fork/exec per token). Recursion is blocked **structurally** via an `origin: hook` meta bit, not a naming convention. Hook executions are themselves recorded + projected for transcript transparency. A **curated subset** of the event taxonomy is frozen as the public contract with independently versioned payloads; the `step_started → agent_step_started` rename happens now, before anyone depends on it.
6. **Security V1 posture:** read hook commands **only from home / `ATELIER_CONFIG`**, ignoring repo-local `./atelier.toml` hooks — this deletes RCE-on-clone by construction (one branch in the loader). Payload reaches the hook **stdin-only, with no argv/command templating** (a written invariant, to prevent content-injection from home hooks). **Data-minimization**: metadata-only on stdin by default, opt-in to full payload. Redaction (`redact_sensitive_text`) is hardened beyond `Bearer`/`sk-`/`zai-` but billed as hygiene, not a boundary. An **egress allowlist** governs atelier's own audit-shipping destinations. The hash-pinned **trust-gate design is recorded now** as the gating seam for when repo-local/project hooks arrive.
7. **Blocking PreAction veto is deferred to V2**, reusing `ActionDecision::Denied` + `ApprovalMode` + the *same* dispatcher + the *validated* payload schema.

## Alternatives Considered

### Alternative 1: Notify-first observer V1 (the original framing)

- **Description**: Observer hooks anchored on desktop-notify-on-approval; success = reduced `WaitingForUser` idle time.
- **Pros**: Cheapest; a real convenience win; the dispatcher is event-agnostic so build cost is low.
- **Cons**: Parity/me-too with all three incumbents; the success metric is pinned near-zero by atelier's `yolo` default (no approvals fire); risks shaping the payload schema for the trivial case (schema capture), which is the wrong shape for the V2 veto.
- **Why rejected**: Demoted to a secondary slot rather than the flagship — it buries the one edge competitors can't copy.

### Alternative 2: Governance-gate-first (V2-first blocking)

- **Description**: Skip observers; lead with one audited blocking cross-runtime policy gate (deny-command / deny-write-outside-roots / require-approval), measured by violations prevented.
- **Pros**: Highest differentiation and defensibility — the only cell where portability is load-bearing; violations *prevented* > *recorded*.
- **Cons**: Sits on the action hot path and a security boundary before the cross-runtime payload schema has been validated; a false-block wedges legitimate runs (adoption killer) and a false-allow is advertised assurance that becomes a liability — a janky gate *is* the Gartner cancellation failure mode.
- **Why rejected**: Re-sequenced as V2, built on the schema that observer-V1 validates read-only and reversibly first.

### Alternative 3: `events --follow` only (no hook subsystem)

- **Description**: Ship a stable JSON event stream over the existing JSONL plus docs; users host their own integrations.
- **Pros**: ~1 day of work; honest cash-out of "audit is inherent"; no shell-in-the-loop security surface.
- **Cons**: User-hosted, pull-only (needs an attached terminal); no turnkey/uniform cross-runtime dispatch; weak differentiation; no on-ramp to the V2 veto.
- **Why rejected**: Absorbed as a *component* of V1, not the whole bet.

## Consequences

### Positive

- Ships real value now at low (read-only) risk while laying the exact schema rails the differentiated V2 governance gate needs.
- Anchors on the structurally-hard-to-copy cross-runtime audit job → addresses the #1 enterprise governance gap.
- Keeps the cheap notify win and the near-free `events --follow` DIY path.
- Security surface minimized by construction (ignore repo-local; stdin-only, no templating).

### Negative

- Higher upfront design cost than notify-first — the uniform cross-runtime payload schema is genuinely the hard part.
- The "integration platform" framing is aspiration until adoption proves it; V1 must resist platform-grade scope creep.
- Demoting notify departs from the original solo-dev anchor and its chosen success metric.

### Risks

- **Schema capture** (payload designed for notify, wrong for veto) → mitigate with decision-first schema design reviewed against the V2 veto's needs before freezing.
- **Data egress via home-config hooks** (`curl -d @-`) → mitigate with metadata-only stdin default, hardened redaction, a documented leak path, and an egress allowlist for built-in shipping.
- **Repo-local hook demand** (husky / pre-commit / direnv precedent: per-project hooks are the most-requested feature in every comparable) → "don't support repo-local" is a deferral, not a decision; record the trust-gate design now as the seam.
- **Hot-path stall** → off-funnel bounded-channel dispatcher + `kill_on_drop` + timeout + explicit drop/coalesce backpressure; never `.await` at the write site.

## Implementation Notes

Verified integration points: tap `record_event_with_group` (`src/app/mod.rs:4215`) by `try_send` onto a bounded channel — **not** an inline spawn; the dispatcher reuses the idiom at `src/app/git.rs:68` / `src/runtime/codex.rs`. `redact_sensitive_text` (`src/runtime/mod.rs:704`) needs hardening beyond its current `Bearer`/`sk-`/`zai-` denylist. Chat projection (`src/app/chat/projection.rs:58`) gains `hook_started` / `hook_completed` handlers (recorded with the `origin: hook` meta so the dispatcher tap ignores them — closing recursion *and* replay double-fire). Config ladder (`src/config/mod.rs`): add `HooksConfig` / `RawHooksConfig`, and drop the Local layer's hooks. V2 veto grounding: `ActionDecision::Denied` (`src/actions/mod.rs:91`), `validate_action_request_with_scope` (`:145`), `ApprovalMode` (`src/config/mod.rs:20`).
