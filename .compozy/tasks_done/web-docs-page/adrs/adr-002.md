# ADR-002: V1 docs product approach — differentiation-led activation surface

## Status

Accepted

## Date

2026-06-12

## Context

ADR-001 set the V1 scope: a small multi-page `/docs` section + a source-derived
reference generator + `llms.txt`, shipped alongside the README, with the README→pointer
canonical flip and an in-product `/help` RAG deferred to V2. The PRD clarification round
then settled four product decisions:

1. **Quickstart framing:** lazy + fake-first — there is no credential-free path to a
   *real* run (the orchestrator defaults to `zai` and needs `ZAI_API_KEY`; default worker
   agents need a `codex` login; only the `fake` runtime is zero-setup, and it simulates).
2. **Page set:** add a **Concepts** page and fold Troubleshooting (generated from
   `--doctor`) into the Quickstart, instead of a standalone Troubleshooting page.
3. **Build phasing:** ship V1 in **two waves**.
4. **Metrics:** **instrument-free** — no user tracking on the static site.

Three approaches were weighed for the overall *emphasis* of V1.

## Decision

Adopt the **differentiation-led activation surface** approach. The docs lead with what
the competitor category (a Mintlify monoculture that documents capabilities, not
governance) does not:

- A **flagship Governance & Safety page** ("what an agent can and can't touch" + the
  durable, replayable record).
- A **Concepts page** framing the control-plane / run-lifecycle mental model.
- A **lazy + fake-first Quickstart** that turns the first *approved write* into the
  activation "aha" for the safety model.
- **First-class machine-readability**: `llms.txt` + `llms-full.txt` + per-page Markdown
  twins, so LLMs cite Atelier accurately.
- **Configuration and CLI reference generated** from the Rust source of truth.

Ships in two waves alongside the README; success measured with instrument-free metrics.

**The five V1 pages and their Diátaxis roles:** Quickstart (Tutorial) · Concepts
(Explanation) · Governance & Safety (Explanation + How-to) · Configuration (Reference,
generated) · CLI & Commands (Reference, generated). **Wave 1** = Quickstart + Concepts +
Governance + shared layout + `llms.txt`; **Wave 2** = the two generated reference pages +
Markdown twins + `llms-full.txt`.

## Alternatives Considered

### Alternative 1: Conventional getting-started + reference

- **Description**: Standard Quickstart + Configuration + CLI reference spine; Governance
  is one ordinary page among five; `llms.txt` is a minor add-on.
- **Pros**: Lower risk, familiar, fastest to design.
- **Cons**: Looks like the category; under-uses the control-plane differentiator; weaker
  LLM-citability; lower ceiling.
- **Why rejected**: Forfeits Atelier's only unclaimed docs differentiation.

### Alternative 2: Lean activation MVP

- **Description**: Ship only the three hand-written pages (Quickstart, Concepts,
  Governance) + `llms.txt` as V1; defer the generated reference to a fast-follow.
- **Pros**: Smallest, fastest; validates the activation thesis before investing.
- **Cons**: Leaves Configurer Cora without reference at launch; revises the agreed
  "both waves in V1" decision; the README's reference drift persists longer.
- **Why rejected**: Under-serves half the audience and contradicts the two-wave-in-V1 plan.

## Consequences

### Positive

- Strongest differentiation; the corpus compounds directly into the V2 in-product
  `/help` RAG.
- Both personas served (evaluator via Quickstart/Concepts/Governance; configurer via the
  generated reference).
- LLM-citable from launch via `llms.txt`.
- Conversion-led page ordering with a sub-5-minute first-run north star.

### Negative

- More upfront prose design for the Governance and Concepts pages.
- The generator establishes a new repository pattern (no `xtask`/codegen precedent).
- The two reference pages land in Wave 2, slightly after the first ship.

### Risks

- The Quickstart's fake-first framing could read as "the tool needs fakery to demo" →
  frame `fake` as an explicit zero-setup *preview* and drive quickly to a real run.
- The Governance page could over-promise → keep every claim source-anchored and include
  an honest-limits note.
- Generator scope creep → emit from the existing `--print-config` / `--doctor --json`
  surfaces; add only a one-line enabler to expose the slash-command catalog.

## Implementation Notes

- Wave 1 pages are hand-written and unblock the first deploy; Wave 2 reference pages
  consume the generator.
- Extract a shared `web/src/layouts/Base.astro` before adding pages.
- The CI link-check gate is a **new** PR-triggered `web/`-checks workflow, not a bolt-on
  to the existing `pages.yml` (which fires only after merge to `main`).
